    Future fields and controller registration¶

    The specified registration contract already provides typed declarations, per-element version/capability negotiation, must-ignore grammar members, namespaced extensions and declared legacy carriers (sections 2-5). It is specified, not implemented. It can describe and negotiate future controller fields; it does not make an otherwise unrepresentable value storable, bypass authorization or authorize arbitrary schema execution. Legacy POST does not acquire a registration prerequisite. Unknown representable fields and unsupported storage shapes are different contracts; future schema upload does not waive current compatibility testing.
