OPERATOR-VISIBLE BEHAVIOUR CHANGES
List every change an operator will NOTICE, numbered, each with the
mechanism in one or two sentences. This list is the contract with
release-notes.md: the notes must carry every item on it. State that,
in these words or better:

  "These N things are not bug fixes from the operator's chair, and the
   release notes carry all N. Do not cut this tag until they do."

Anything here that could mislead if compressed must carry its own
correction inline. The models to copy:
  - "It fires in ONE evaluation window and does not repeat. Do not
     describe it as repeating."
  - "A vendor outage will LOOK slower to recover. It is not slower."

REMEDIATION FACTS
Anything a code fix does NOT accomplish, that an operator must therefore
do by hand. Security fixes are where this bites: a fix that stops a
secret being WRITTEN does not invalidate secrets already written. Name
the operator's levers explicitly. BF-17 in the 15.0.9 draft is the model.
