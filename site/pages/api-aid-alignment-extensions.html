AID 2026 Alignment Extensions (2026.1.0)

Download OpenAPI specification:

License: AGPL-3.0

OpenAPI specification for proposed 2026 alignment extensions that address documented gaps across the AID ecosystem.

Design Philosophy

  • Extensions are additive (backward compatible)
  • Marked with x-aid-2026: true annotation
  • Each extension references specific GAP-XXX it addresses
  • Can be adopted incrementally by controllers

Implementation Priority

  1. Critical: Identity and authority (GAP-003, GAP-AUTH-001)
  2. High: Override lifecycle (GAP-001, GAP-002)
  3. Medium: Data provenance (GAP-CGM-001 through GAP-CGM-006)
  4. Low: Enhanced metadata (trend rates, insulin curves)

EntryExtended

_id
string

Storage key Nightscout assigns. API v3 does not return it and refuses a request body that carries it (400). See "API versions" above.

identifier
string

The record's sync identity, assigned by the client and the same on every retry; it need not be a UUID. When a client sends none, API v3 computes one; a document stored without one is read back through API v3 with its _id string as identifier. Immutable once stored. See "API versions" above. Used for document addressing in v3 endpoints.

type
required
string (EntryType)

Entry classification:

  • sgv: Sensor Glucose Value (CGM reading)
  • mbg: Meter Blood Glucose (fingerstick)
  • cal: Calibration record

Open: these are the known values, not a closed list. Nightscout stores any string here: API v1 refuses only a type that is not a string (cgm-remote-monitor lib/server/entries.js) and API v3 does not check it. A reader must accept a value it does not know.

sgv
number

Sensor glucose value in mg/dL. Required when type=sgv.

mbg
number

Meter blood glucose value in mg/dL. Required when type=mbg.

direction
string (Direction)
Enum: "DoubleUp" "SingleUp" "FortyFiveUp" "Flat" "FortyFiveDown" "SingleDown" "DoubleDown" "NOT COMPUTABLE" "RATE OUT OF RANGE" "NONE"

Glucose trend direction. Maps to rate of change:

  • DoubleUp: > 3 mg/dL/min
  • SingleUp: 2-3 mg/dL/min
  • FortyFiveUp: 1-2 mg/dL/min
  • Flat: -1 to 1 mg/dL/min
  • FortyFiveDown: -1 to -2 mg/dL/min
  • SingleDown: -2 to -3 mg/dL/min
  • DoubleDown: < -3 mg/dL/min

ProfileExtended

timezone
string

IANA timezone name

dia
number [ 2 .. 10 ]

Duration of Insulin Action in HOURS, as written to the profile document. The 2-10 bounds below describe stored values; each controller applies its own limits to its own DIA setting, and the value in a Nightscout profile is not necessarily the value a controller doses with.

  • oref0 (d219baf9) takes DIA from pump settings (insulin_action_curve, lib/profile/index.js:117-122), raises a value below 3 h to 3 h (lib/iob/total.js:23-27), and a value below 5 h to 5 h for the exponential curves rapid-acting and ultra-rapid (lib/iob/total.js:59-63).
  • Trio (0b29cd534) carries the same JavaScript (trio-oref/lib/iob/total.js:21-25, 57-61). Its Swift profile generator refuses a DIA below 5 h (APS/OpenAPSSwift/Profile/ProfileGenerator.swift:124-129) and its Swift IOB calculation raises one below 5 h to 5 h (APS/OpenAPSSwift/Iob/IobCalculation.swift:151-156). It uploads its own pump-settings DIA in the profile (Services/Network/Nightscout/NightscoutManager.swift:822).
  • AAPS (7e1d537d49) marks a profile invalid when DIA is outside 5-9 h, or 5-10 h for the pregnant age type (core/interfaces/.../utils/HardLimits.kt:36-42, core/objects/.../profile/ProfileSealed.kt:191-196).
  • Loop (LoopKit d9f14373) has no DIA setting: the duration is fixed by the selected exponential insulin model, 6 h, or 5 h for Afrezza (LoopKit/Insulin/ExponentialInsulinModelPreset.swift:21-34). It uploads a fixed dia of 6 h in the profile (NightscoutService 2cef489, NightscoutServiceKit/Extensions/StoredSettings.swift:83).

AlignedTreatment

_id
string

Storage key Nightscout assigns. API v3 does not return it and refuses a request body that carries it (400). See "API versions" above.

identifier
string

The record's sync identity, assigned by the client and the same on every retry; it need not be a UUID. When a client sends none, API v3 computes one; a document stored without one is read back through API v3 with its _id string as identifier. Immutable once stored. See "API versions" above. AAPS uses this for sync identity.

syncIdentifier
string

Client-assigned sync identity (UUID). Loop and Trio primary sync mechanism.

eventType
required
string (EventType)

Treatment classification. This is the primary discriminator for treatment types. Note: The same eventType may have different semantics across controllers.

Open: the values below are the known ones, not a closed list. Nightscout stores any string here: API v1 refuses only an eventType that is not a string (cgm-remote-monitor lib/server/treatments.js, validateDedupFields), API v3 only makes it immutable on update (lib/api3/generic/update/validate.js:71), and WRITE_VALIDATION checks the targets of a Temporary Target without restricting the vocabulary. A reader must accept a value it does not know (QUIRK-TREATMENTS-005).

Known values:

  • insulin: Meal Bolus, Correction Bolus, Snack Bolus, Combo Bolus, Bolus Wizard
  • carbs: Carb Correction
  • basal, targets and profiles: Temp Basal, Temporary Target, Profile Switch, Temporary Override
  • device and notes: Site Change, Sensor Start, Sensor Change, Insulin Change, Pump Battery Change, BG Check, Announcement, Note, Question, Exercise, OpenAPS Offline, Suspend Pump, Resume Pump
  • AAPS-specific: SMB, Target Range, NS Carbs
  • observed in live data, previously undeclared: Bolus, Carbs
  • legacy: Prime, <none>
created_at
required
string <date-time>

Event timestamp (ISO 8601)

timestamp
string or number

Alternative timestamp to created_at.

Declared integer by the 2025 spec and observed as a string in 100% of its 311,648 occurrences across 10 sites — an ISO 8601 datetime, not epoch milliseconds. number is retained because clients that do write epoch milliseconds are plausible and the corpus is Loop-dominant; a reader must handle both.

insulin

What the user intended:

  • switch: Change to different profile
  • percentage_adjustment: Same profile, different intensity
  • time_shift: Same profile, shifted schedule
  • target_override: Temporary target change
  • combined: Multiple modifications
