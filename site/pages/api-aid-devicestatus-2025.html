OpenAPI specification for the Nightscout devicestatus collection documenting the de facto standard as implemented across AID systems circa 2025.

API versions

The operations declared here are Nightscout API v3 as shipped on cgm-remote-monitor dev 47723cda (lib/api3/swagger.yaml). The document schema describes the stored devicestatus document, which clients write through API v1 or API v3: Loop (NightscoutKit NightscoutClient.swift:13-17) and Trio (NightscoutAPI.swift:14-18, 0b29cd534) use API v1; AAPS uses API v3 (core/nssdk/.../networking/NightscoutApi.kt). The x-aid-controllers notes describe what each controller writes, through whichever API it uses; they are not API v3 behaviour.

In API v3:

  • a successful response is wrapped as {status, result} (lib/api3/shared/renderer.js:117-122);
  • identifier is the record's sync identity, assigned by the client; when none is sent the server computes one (lib/api3/shared/operationTools.js:209-216), and a document stored without one is read back with its _id string as identifier (lib/api3/storage/mongoCollection/utils.js:10-16);
  • _id is the storage key Nightscout assigns: API v3 does not return it (utils.js:10-16) and refuses a create or update body that carries it with 400 (operationTools.js:197-203, called from generic/create/operation.js:35 and generic/update/operation.js:32). API v1 keeps its own _id handling.

Critical Structural Difference

  • Loop: Uses loop top-level object with flat structure
  • oref0-based (AAPS, Trio, OpenAPS): Use openaps with nested structure

Prediction Formats

  • Loop: Single combined prediction array
  • oref0: Four separate curves (IOB, COB, UAM, ZT)

Changelog

2025.2.0 — corrected against measured data

Reconciled against 702,254 real device-status documents from 11 Nightscout sites (reports/schema-census/devicestatus.census.json). Evidence and method: docs/30-design/platform/nightscout-typed-schema-evidence-2026-09-10.md.

  • PumpStatus: the flat status shape (pump.bolusing, pump.suspended, pump.pumpID, pump.secondsFromGMT, pump.manufacturer, pump.model) is documented for the first time. It is written by 10 of 11 sites; the nested pump.status.* shape this spec previously described alone is written by 1.
  • PumpStatus.battery: added string and display; marked the declared status and voltage as never observed.
  • UploaderStatus: added timestamp (10 sites), isCharging, type.
  • Oref0IOB.lastTemp.duration: integer -> number (97.2% fractional).
  • Documented the 0xDEADBEEF reservoir sentinel.

Fields carry x-aid-evidence pointing at the census record that justifies them. Re-derive with make schema.
