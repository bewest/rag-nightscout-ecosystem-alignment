Nightscout 15.0.9 journeys

What people actually do with Nightscout, from an empty site to a clinic-visit report, written as steps you can check. Each step says what to do, what working looks like, and what to watch for. The contributor view adds what each app sends and where the lab replays it.

Not medical advice. This describes what software does so that testers can check it. It never tells anyone what insulin to take or which settings to use. Every therapy value in the lab is a made-up test value. For changes to your own or a family member's settings, talk to your care team.

Words used here

Nightscout sitethe web page and database a person runs for their own diabetes data
AID appan automated insulin delivery app on a phone: Loop, Trio or AndroidAPS (AAPS)
Profilethe therapy settings: basal rates, insulin sensitivity (ISF), carb ratio, targets, insulin duration (DIA)
Careportalthe site's own form for entering treatments and events, the + button
Profile Editorthe site's page for entering or changing a profile (menu → Profile Editor)
Override(Loop, Trio) a temporary change to targets and insulin needs, e.g. "Running" for 90 minutes
Temp target(Trio, AAPS) a temporary glucose target, e.g. 140 mg/dL for an hour
Profile switch(AAPS) changing to another profile, or the same one at a percentage
API secretthe site's master password; whoever has it can change anything
Tokena limited-access link made on the site's admin page, e.g. read-only for a follower
IOB / COBinsulin on board / carbs on board
Device statusthe app's regular report: loop status, pump battery, predictions

Starting on an AID appset up a new site, connect the app, see their data

An experienced useroverrides, temp targets, new profiles, fixing wrong entries
A follower or caregiversees data, gets alarms, may enter carbs or send a remote command

J1.0

Open the new site

DoOpen the site's address and log in with the API secret.
WorkingOne message, "Redirecting you to the Profile Editor to create a new profile.", then the Profile Editor opens. It appears once, not in a loop.
Watch forThe message repeating; a blank page; an error instead of the Profile Editor.
checked in a browser 2026-09-26lab: any empty site

Path A · the app first

J1.A1–A2

Connect the app

DoEnter the site address and the API secret (Loop, Trio). AAPS 3.4 with NSClient v3 asks for a token made on the admin page with the admin role, not the API secret.
WorkingThe app says it is connected (Trio also posts a "Trio connected" note). With nothing to import, the app goes on to its own setup.
Watch forThe app saying the secret or token is wrong when it isn't.
lab: loop | trio | aaps · connect
J1.A3

The app sends its settings

DoFinish the app's setup so it saves its therapy settings.
Working
  • The Profile Editor shows the app's basal rates, ISF, carb ratios and targets in the right units.
  • The main page stops redirecting and draws the basal line.
  • Loop sites: careportal offers Temporary Override with Loop's presets.
Watch forValues in the wrong units; times shifted by hours (time zone); the redirect still happening. When the profile arrives differs: Loop at "Save Settings"; Trio not at the end of onboarding but at the next full relaunch or first settings edit (the site keeps redirecting until then); AAPS on save, then a required profile switch. An open Profile Editor does not refresh by itself: reload it.
checked in a browser 2026-09-26lab: onboard, status, trio finish-onboarding, aaps wizard
J1.A4

The app starts sending data

DoLet the app run for a while.
WorkingReadings every 5 minutes; boluses, carbs and temp basals on the chart; the loop pill shows a recent time; IOB, COB, reservoir and battery close to the app.
Watch forA pill stuck on an old time while the app runs; duplicate boluses or carbs.
lab: backfill, tick, live

Path B · the site first

J1.B1–B2

Type a profile into the Profile Editor and save it

DoReplace every starting value with the person's own, pick the time zone, and save (needs the API secret).
Working"Default values used" shows until real values are saved. After a reload the values stay and the main page draws the basal line. On 15.0.9 the first save works as filled in; 15.0.8 refused it until a start date after 1970 was chosen.
Watch for · safetyThe starting values are placeholders: DIA 3 h, carb ratio 30, ISF 100, basal 0.1 U/h and targets of 0. The page lets you save them unchanged (so does 15.0.8). The time zone starts as UTC, not the browser's. Note how visible the warning is.
checked in a browser 2026-09-26lab: cp-loop | cp-trio | cp-aaps · by hand (editor-save automates it)

Path E · CGM first, through the built-in connector

J1.E1

Turn on the connector

DoAdd connect to ENABLE; set CONNECT_SOURCE=dexcomshare with the Share account name, password and region (or linkup with the LibreLinkUp login).
WorkingUp to 2 days of Dexcom history (about 12 h from LibreLinkUp) within a minute or so, then a reading every 5 minutes, each from nightscout-connect. The page still redirects to the Profile Editor: the connector brings readings only, so the chart stays hidden until an app sends a profile.
Watch forA typo in CONNECT_SOURCE starts quietly with a built-in test driver instead of the real one.
checked in a browser 2026-09-26lab: cgm-loop · cgm-trio · cgm-aaps, share, cgm-status

Paths F and G · caregivers, and changing apps

J1.F–G

A caregiver's app starts from the site; moving between apps and versions

CaregiversAAPSClient takes the profile and every treatment (100 days). LoopFollow and LoopCaregiver read the newest profile for remote-command details and presets.
ChangingAAPS v1 → v3 downloads 100 days again. 3.4 → 4.0 drops v1, so a v1 user may need to turn on v3 (unconfirmed). Loop ↔ Trio: neither imports the other's profile; the newest wins, so Loop-only features stop after Trio takes over.
Found by the labAfter any new profile, remote commands keep going to the phone in the previous profile until the site next reloads its data: the next upload, or at the latest about a minute later (JL-2, also on 15.0.8).
found JL-2lab: client-bootstrap, switch-to-trio, new-phone
J2

Everyday data flowing in

J2.1–J2.5

Readings, treatments, pills and followers

DoWatch the main page as the app uploads. Enter a Site Change and a Sensor Start from the careportal. Open a follower link in another browser profile.
Working
  • Trend arrows and "minutes ago"; gaps show as gaps.
  • COB says where it came from (Loop or OpenAPS).
  • Loop/OpenAPS pill shows what the loop did; a prediction line.
  • Cannula and sensor age reset.
  • The follower's page updates by itself.
  • Two carb entries at the same time, with different amounts, are both kept (fixed in 15.0.9).
Watch forCOB or IOB very different from the app; duplicates; a follower page that needs reloading. Two careportal entries in the same minute with the same amount are still stored as one.

J3

Changing things for a while (day 2)

J3.1–J3.2

Start an override or temp target in the app, then end it early

DoStart one in the app, check the chart, then end it early.
WorkingA bar with the name and length; after ending, the bar stops at that time, without a reload, and there is one record, not two. A temp target shows as a thin grey bar at the target.
Differences, not defectsLoop sends "indefinite" as indefinite. Trio sends it as 30 days (43200 min), labelled Exercise with the name in the notes, and doesn't send the percentage or target.
checked in a browser 2026-09-26 (AAPS temp target)lab: override-start / -end, tt-start / -end / -cancel
J3.3

Start one from the site's careportal

DoLoop: Temporary Override → a preset. Trio: Temporary Target. AAPS: Temporary Target or Profile Switch.
WorkingLoop: the site sends a push to the phone (needs the API secret or admin, and Loop's profile newest); the override appears on the chart once Loop uploads it. Trio picks it up only with "Allow downloads" on. AAPS applies it only if its "accept … from Nightscout" setting is on.
Watch forWhen a Loop command succeeds, the careportal just closes, with no message (the same on 15.0.8); only a failure shows one. Check on the phone that it arrived before sending it again.
checked in a browser 2026-09-26 (override, remote carbs, cancel)lab: apns, downloads, accept-check
J3.4

Profile switch with a percentage (AAPS)

DoTurn on the basal display, then switch to a profile at 150%.
WorkingThe switch shows in the chart's basal area. The basal pill and its pop-up follow the percentage the way AAPS does: basal × 1.5, ISF and carb ratio ÷ 1.5. Checked: 0.950 → 1.425 U/h, ISF 2.8 → 1.87, carb ratio 12 → 8; 15.0.8 showed the 100% values.
Known issueThe pop-up shows the scaled ISF unrounded, for example 1.866666666667 (JL-5, cosmetic). If AAPS uses Dynamic ISF, the ISF it doses with can differ from the one shown.
fixed BF-123 · checked 2026-09-26known JL-5 unrounded ISFlab: ps-start 150 0 LabDay
J3.5–J3.6

Change settings in the app, or make a profile on the site

DoChange a basal rate in the app. Separately, Profile Editor → Add new → Save.
WorkingEach change is a new profile record; the newest is used; a new Loop preset appears in the careportal without a reload.
Watch for · Loop sitesAfter a profile made on the site, remote commands and override presets stop working ("Could not find loopSettings in profile") until Loop sends its settings again. Reports → Profiles can miss profiles saved later on the report's last day (JL-3).
known JL-3 Reports → Profiles, last daylab: settings-change, new-phone, caregiver-override
J4

Fixing mistakes

J4.1–J4.2

Edit or delete on the site

DoIn edit mode, drag a treatment; in Reports → Treatments, edit one and delete one.
WorkingChanges stay after a reload; the chart follows without a reload; IOB and COB follow the new time. An edit to an AAPS entry now reaches AAPS's sync history (fixed in 15.0.9).
Which way changes travelSite changes do not go back to Loop or Trio. A delete on the site never reaches AAPS: delete in AAPS as well. Right after an edit or delete, the Treatments table can still show the old row until you press Show again (JL-6).
fixed BF-122 · checked 2026-09-26known JL-6 table shows the old rowknown BF-124 tooltip unit conversion
J4.3

Edit or delete in the app

DoDelete a carb entry in the app.
WorkingLoop and Trio: the entry is gone from the site. AAPS: the entry leaves the chart and COB without a reload (fixed in 15.0.9; 15.0.8 kept counting it).
Watch forA deleted entry still on the chart, in COB or in reports.
fixed JL-1 / BF-135 · checked 2026-09-26lab: carbs, carb-delete
J4.5

Delete a profile record

DoProfile Editor with two or more records: delete the older one.
WorkingOnly that record goes. Deleting one named profile inside a record takes effect on Save.
Watch forThe wrong record going; the newest changing unexpectedly.

Looking back: reports

J6.1–J6.6

Two weeks, then ninety days

DoReports with a token or the secret. Last 14 days: Day to day with IOB, COB and basal ticked; then Daily Stats, Distribution, Hourly, Percentile, Weekly, Treatments, Profiles, Loopalyzer. Then 90 days: Week to week and Percentile.
WorkingEvery day drawn; pages agree on reading counts and roughly on averages and time in range; the Treatments event-type filter (new in 15.0.9) narrows the list; mmol/L sites stay in mmol/L; ranges over 186 days are refused.

Findings from walking the journeys

JL-2, mechanism found. Profile create, save and remove emit data-received before the database write completes (lib/server/profile.js:90,130,210). The reload on the debounce's leading edge (lib/server/bootevent.js:349) reads the previous profile, and ctx.ddata.profiles[0], which lib/server/loop.js reads, stays stale until the next write or the 60 s heartbeat. Measured with no other writes: the previous token at 2 s, the new token from 60 s, on both trees. Recorded as GAP-REMOTE-010; the classification is open to review now that the mechanism is known.
