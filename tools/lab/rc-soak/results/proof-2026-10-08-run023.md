## Brush-extent behaviour (#8807)

#8807 changes only `lib/client/chart.js` and its tests; it is **client-only**, so the A/B soak
cannot reach it and the A/B verdict is unchanged from run 022. The fix is covered where it lives:

- On any head before #8807 (15.0.8 and 43289dde included), d3's `brushX` with no explicit `.extent()`
  reads the context `<svg>`'s own width and height. When the chart is first drawn before the browser
  has laid the page out, that size is the SVG default 300×150, so the brush's draggable area is
  clamped to the stale 300-pixel width and the context window cannot be dragged all the way back to
  "now" after the chart is later resized. #8807 declares the extent from the chart's own scale and
  height, and has `chart.update()` re-read it and rebind the overlay, so the window drags to now
  regardless of draw order. This is a display-only fix in the secondary-display chart; it does not
  change any stored data or any API reply.
- It is live on 15.0.8 too, so this file states the mechanism only, not a reproduction recipe.
- It is covered by the two new `tests/dependency-d3.test.js` cases (`mouse` and `touch`), green in
  every suite cell: the fixture draws the chart before layout and the test asserts the dragged
  window reaches now — red without #8807's change, green with it.
- The gate section above records that `lib/client/chart.js` has entered the browser hand-check
  surface, so a chart-drag hand check at fade2299 is owed.
