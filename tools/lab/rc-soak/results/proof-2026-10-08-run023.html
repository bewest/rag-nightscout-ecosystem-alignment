    What this run adds over run 022¶

    Run 022 (proof-2026-10-07-run022.md) proved official/dev at 43289dde. Since then the 15.0.9 release head has advanced by one merge to fade2299 = 43289dde + PR #8807 (BF-168, the context-chart brush-extent fix). git diff 43289dde fade2299 is exactly three files, all client/test, zero server/API code:

    • lib/client/chart.js (+8): the d3 brushX now declares an explicit .extent() (the context chart's own width and height), instead of letting d3 read the <svg> element's own size, which is the browser default 300×150 when the chart is drawn before layout settles; and chart.update() re-reads the extent and rebinds the brush overlay so the context window can still be dragged back to "now" after a resize.

    • tests/fixtures/d3-chart.js (+17/−4): the fixture gains an optional layout argument; with layout undefined it behaves exactly as before.

    Brush-extent behaviour (#8807)¶

    8807 changes only lib/client/chart.js and its tests; it is client-only, so the A/B soak¶

    cannot reach it and the A/B verdict is unchanged from run 022. The fix is covered where it lives:

    • On any head before #8807 (15.0.8 and 43289dde included), d3's brushX with no explicit .extent() reads the context <svg>'s own width and height. When the chart is first drawn before the browser has laid the page out, that size is the SVG default 300×150, so the brush's draggable area is clamped to the stale 300-pixel width and the context window cannot be dragged all the way back to "now" after the chart is later resized. #8807 declares the extent from the chart's own scale and height, and has chart.update() re-read it and rebind the overlay, so the window drags to now regardless of draw order. This is a display-only fix in the secondary-display chart; it does not change any stored data or any API reply.
    • It is live on 15.0.8 too, so this file states the mechanism only, not a reproduction recipe.
    • It is covered by the two new tests/dependency-d3.test.js cases (mouse and touch), green in every suite cell: the fixture draws the chart before layout and the test asserts the dragged window reaches now — red without #8807's change, green with it.
    • The gate section above records that lib/client/chart.js has entered the browser hand-check surface, so a chart-drag hand check at fade2299 is owed.
