    record-identity lab results, 2026-10-18¶

    Record

    Record as of 2026-10-18. A point-in-time document; it is not kept up to date.

    Contributor-facing. Synthetic data only; nothing here is from a real site.

    Produced by tools/lab/record-identity/lab.sh up && lab.sh run (see README) with:

    RID_REPO=<main checkout>/externals/cgm-remote-monitor-official
RID_BUILDS="1508=15.0.8:3983 dev=fade2299:3984"            # the default
RID_NM_1508=externals/work/crm-6a-replay-a/node_modules    # same package-lock.json as 15.0.8 (checked by cmp)
RID_NM_dev=externals/work/crm-rc-018-n20/node_modules       # same package-lock.json as fade2299 (checked by cmp)
RID_NODE=<n>/versions/node/22.23.2/bin/node
    build what head /api/v3/version
    1508 15.0.8, the shipping release 92d08342 15.0.8, apiVersion 3.0.5
    dev official/dev fade2299 15.0.9 (package version on dev), apiVersion 3.0.5

    MongoDB: dedicated container ridlab-mongo, mongo:7, server version read back 7.0.43. Node 22.23.2. UUID_HANDLING unset (default on). v1 calls carry the api-secret hash, v3 calls a JWT for an admin subject the probe creates, the socket authorizes with the hash. The probes were run four times (three against one pair of servers, one after a fresh up); every cell was the same each time, except the order of two records in one cell, which the probe now sorts, and the treatments GET row, whose case-sensitivity probes were corrected before the fourth run.

    How to read a cell: HTTP status (and the MongoDB cause when the reply body names one), then what is stored, read from mongo: n= copies, each with _id:oid (an ObjectId) or _id:string, =sent / ≠sent against the _id the client sent, and identifier=X when it equals the value the case sent as identifier (or as _id, for the cases that test UUID_HANDLING). reply says whether the reply item's _id is the one sent, the one stored, both, or absent. Times are one minute apart per case, 1 to 2 days back.
