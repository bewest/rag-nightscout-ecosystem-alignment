    Bounded Kubernetes workload inputs¶

    Living document, last changed 2026-11-23 at b95ecafed.

    Living contributor-facing instrument guide. Definitions are read-derived from the existing M7 generator and frozen C2 core 6463f24eea02a9e4355d988b1353f238f21d3609; local generator/retained-data controls are reproduced on 2026-11-17 Pacific. Kubernetes operation, production traffic and capacity admission are UNMEASURED here. The production guide owns the workload model. Adopted performance policy and capacity policy retain their existing homes.

    These files supply inputs and independent reductions to the existing Kubernetes adapter. They start no Kubernetes actor, reserve no resource and add no capacity gate.

    Source mapping and scope¶

    Source anchor Supported meaning
    tools/mt-bench/capacity/k6/workload.js:47 (ALL_SHAPES), adapted by tools/mt-bench/m7-joined/workload.py:7 Seven shapes: one entries, one devicestatus and one v3 treatment write; five latest-SGV, one devicestatus, one treatments and one status read per weighted cycle. Weights are assumptions taken from the existing synthetic client-shaped mix, not observed production frequencies.
    C2 lib/tenant-connector/config.js:40, runtime.js:73 Connector defaults: five-minute successful-poll cadence, 15-second scheduling cycle, 150-second retry delay. Poll eligibility and records actually returned are distinct from a write per tenant every poll. These profiles do not start connectors.
    C2 lib/client/index.js:1165 and 1166; original capacity/probe.js:61 Stock display and alarm namespaces use Socket.IO polling transport. A connected stock viewer is not one REST request per clock tick. The M7 probe opens the data namespace; it does not prove the separate alarm-namespace journey.
    m7-joined/workload.py:27 and kubernetes/execute.py:223 Explicit offeredRps rescales the selected mix; adapter fixes HOT_FACTOR=1, ACCEL=1 and all seven shapes. Integer rate bounds are 1–100 requests/s. The override, not ACCEL alone, defines actual cadence.
    m7-joined/viewer_plan.py:10, capacity/probe.js:8, m7-joined/probe.py:125 logicalPollingClients is the total number of Socket.IO viewers assigned in roster order. Probe writes have their own global round-robin cadence. Ordinary REST reads are driven by k6 independently of viewers.
    C2 lib/server/serve/evaluator-consumers.js:78, :124, :197 Pending/refused/repeating clinical work, persisted attempts and due intents require separate observations. An idle interval with no known opportunity proves no timer progress.

    For the implemented equal-weight roster, let N be ordinary eligible tenants, s_j the shape weight and R the requested ordinary REST rate. M7 computes C_ms = round(1000 × N × sum(s_j) / R) and issues shape j at nominal rate s_j × N × 1000 / C_ms. Here sum(s_j)=11, write weight is 3 and read weight is 8. Ordinary per-tenant ingestion cadence is C_ms, even with ACCEL=1. The extra probe rate is 1000 / probeEveryMs while its window is open. JWT setup, probe priming, Socket.IO HTTP transport and observer SQL are additional work. Startup and finite scheduling boundaries can add one iteration per shape; R × duration is a nominal integral, never a substitute for issued counters/CSV.

    Concrete proposed profiles¶

    The three original aggregate profiles retain two provisioned/ordinary-eligible synthetic tenants and four Socket.IO viewers. They seed no additional history, synthesize no alarm or reconnect flood, and request no restart. Existing provisioner history and retention must be read back; they are not assumed empty or production-sized.

    Input Ordinary window / rate Ordinary cycle Probe cadence Use
    small.json 22 s / 1 request/s 22 s per tenant 300 s globally Small-path diagnostic and native generator shape control
    representative-mix.json 330 s / 1 request/s 22 s per tenant 300 s globally Selected request mix across a nominal five-minute wall-clock interval; ordinary ingestion remains accelerated
    stress-discovery.json 22 s / 10 requests/s 2.2 s per tenant 1 s globally Short overload/discovery point, including explicitly accelerated clinical probes

    The first two offer about 0.273 ordinary writes/s and 0.727 ordinary reads/s; stress offers about 2.727 and 7.273 respectively (read-derived). Even the minimum integer rate accelerates a two-tenant mix by about 13.636. The aggregate selector keeps those original accelerated inputs. Do not describe representative-mix as realistic cadence. The existing released M7 realistic-v1 selector supplies a separate per-shape cadence through the same adapter; it does not round a fractional aggregate rate to an integer.

    Realistic profile Eligible tenants / stock viewers Nominal ordinary REST/s Window
    realistic-500.json 500 / 50 6.9444 1,800 s
    realistic-1000.json 1,000 / 100 13.8889 1,800 s
    realistic-3000.json 3,000 / 300 41.6667 1,800 s

    These are read-derived nominal rates, checked against actual generated k6 scenario options. Sensor and device-status writes and SGV reads recur every 300 seconds per tenant, treatment writes every 1,800 seconds, and other reads every 900 seconds. For shape weight s_j and cadence tau_j_ms, the released generator sets timeUnit = round(tau_j_ms × s_j / workloadScale) and rate = N × s_j. Scale 1 preserves cadence; scale 2 is a uniform rate bracket. Select a positive finite scale explicitly, independent of the roster and viewer total. Every rounded scenario time unit must remain representable by k6. All seven shapes remain required. An offeredRps field alongside realistic-v1, nonuniform hot weighting or conflicting ambient selector refuses.

    The realistic examples retain the exact public reference source/binding tuple from the released scale bridge, not a new candidate selection or source PASS. A successor needs explicitly revised profile pins and its own commissioning packet. Binding rejects a source mismatch; it never silently repins. Their 2.1 CPU cluster limit is an unadmitted proposal from that bridge. Actual resource fit at each population remains UNMEASURED. Each requests a 2,400-second work window plus 600 seconds cleanup. A shorter diagnostic may declare a shorter ordinary window and phase budget, retaining all actual observation limits. The adapter supports 1..86,400 seconds within the real deadline and the stock probe ledger's attempt bound; it does not extend an entered grant.

    For looping workloads, the same populated fixture profile can supply both traffic phases.

    python3 -B tools/mt-bench/kubernetes/workloads/profile.py active seed-10000.json 5000 active-5k load-5k.json
python3 -B tools/mt-bench/kubernetes/workloads/profile.py active seed-10000.json 10000 active-10k load-10k.json

    Both profiles retain the provisioned population and fixture history. The partial phase selects tenants in seed host order and runs ordinary uploads, viewers and probe writes on that group. Driver rates use the client kinds assigned by the full seed. Stored-write and clinical checks cover the whole provisioned population. Full-roster runs keep their existing traffic order. Use distinct point IDs and output directories for the sequential points on one deployment. The active command only writes a workload profile. Two independent standard-case launches each restore their own database.

    The ordinary viewer opens at a configured rate and prefers WebSocket. workload.viewerSetup takes opensPerSecond, stallSeconds, transport (websocket-first or polling) and scenario (ordinary or simultaneous-reconnect). The reconnect scenario first primes the ramped cohort, then reconnects it together and requires fresh frames. Commission and recovery use the stock polling transport. The probe records effective settings and actual transport counts for each connection phase.

    The viewer planner assigns quotient/remainder counts in roster order, including zero-viewer tenants. Storage checks cover all roster writers. Clinical witnesses remain scoped to the independent probe writes; only assigned viewers require client observations. Zero viewers records client delivery NOT_EXERCISED. The bounded raw frame recorder refuses overflow; a longer or larger run does not silently turn lost frame evidence into a pass.

    In discovery load, workload.latencyObservation: offline-v1 disables both the accepted-input SQL observer and the independent probe's writer baseline and per-witness SQL reads. The probe still sends its synthetic entries and records stock viewer frames through the configured drain. The after-run M3 join uses the ordinary driver's accepted writes and that frame ledger. Per-witness clinical completion is NOT_COLLECTED. Stage bookends and storage readback retain their own SQL receipts.

    For a matched control, change only latencyObservation to offline-with-witness-sql-v1. This enables the sparse probe SQL while using the same offered traffic, frame ledger and drain. polling-sql-v1 enables both live observers. An explicit discovery tier defaults to offline observation on every image. Missing evaluator timing evidence leaves the deadline unmeasured. Legacy loads without a tier or observation setting default to offline on durable-M1 images and polling on older images. Smoke and acceptance tiers use polling, and commission and recovery stages always retain their clinical probe.

    Workload profiles carry no resource envelope. Kubernetes requests come from the render; the scheduler decides placement (decisions generous-run-resources, requests-typical-scheduler-decides).

    Small/stress reserve a 900-second work window and representative-mix 1,200 seconds, followed by 600 seconds for exact owned cleanup. These bounds include setup/prime, load and observation/drain; unchanged source timeouts can consume the available window. The work deadline remains authoritative if they overrun. No entry is seeded toward 10,000 tenants by these files.

    python3 -B tools/mt-bench/kubernetes/workloads/profile.py describe \
  tools/mt-bench/kubernetes/workloads/small.json
python3 -B tools/mt-bench/kubernetes/workloads/profile.py dry \
  tools/mt-bench/kubernetes/workloads/small.json /absolute/owned/artifacts/dry01
python3 -B tools/mt-bench/kubernetes/workloads/profile.py bind \
  tools/mt-bench/kubernetes/workloads/small.json \
  /absolute/private/fresh-config.json /absolute/owned/profile-config.json

    bind replaces the selected workload fields after checking the pinned core/image-deployment/binding tuple, roster, planned native envelope and finite fresh deadlines. A changed source requires explicitly revised profile pins and its own focused qualification. Binding a realistic profile replaces the old aggregate selector, rather than retaining an accidental override. Existing successor pointId is preserved to keep markers distinct across reused fixtures; a conflicting hotFactor or unknown workload field refuses rather than silently changing the workload. Pass its output, the exact render and inventory to the existing adapter's prepare. That adapter owns source/content hashes, actual namespace/Pod UIDs, native tools/scope and cleanup. The runtime owner should execute the tiny point only after receiving its finite allocation from commissioning. Frozen C2 source acceptance does not qualify a different binding/instrument, or a changed pending source tuple.

    Observation and completion¶

    Work stage Existing evidence and what it closes
    Configured/offered Profile plus actual environment, roster, generated workload hash, scenario plan, source/image/binding/instrument and time window. Nominal rate is not issued work.
    Issued/responded Per-shape m7_http_attempts, completed/category/status counters and independent scenario counters/CSV. JWT setup stays separate. Missing counters are UNMEASURED.
    Accepted/refused/uncertain Ordinary write outcomes and independent version-2 probe ledger. A timeout or unexpected mutation response cannot establish that the write did not commit; never retry to make the count match.
    Stored Original discovery_counts.observe: marker-scoped per-tenant/per-collection counts bounded by accepted/uncertain writes. A missing accepted row fails M7_DISCOVERY_WRONG_DATA.
    Clinically complete Original captured clinical witnesses, their distinct accepted-write coverage, and optional rerun of the T raw-SQL/typed-output oracle. This reducer checks recorded witness coverage; it does not repeat semantic clinical proof. All-writer completion requires the source-bound fixed input/intake/restore fence and complete backlog observations.
    Delivered Original viewer_plan.check: exact roster/viewer assignment and accepted-probe frame counts. Check authority/isolation independently through T access/raw-frame oracles. ConnectedAtEnd alone cannot prove delivery. 
    python3 -B tools/mt-bench/kubernetes/workloads/reduce.py \
  /absolute/owned/run/load /absolute/owned/reduction01
# Retained M7 fixture instead of a T config:
python3 -B tools/mt-bench/kubernetes/workloads/reduce.py \

python3 -B -m unittest discover -s tools/mt-bench/kubernetes/workloads -p 'test_*.py' -v

    T stores configuration as run.json; the reducer reads that exact contract. Output keeps source/placement/actor identity, independent HTTP and stored results, selected clinical coverage, delivered frames, available stage latency/freshness and 10-second scheduling-count curves. Every retained input is checksummed. It does not mutate originals. A lost witness fails coverage even if the recorded top-level clinical verdict says PASS; dropped iterations are a figure by operation and erase no accepted/stored/selected-clinical observation. That is coverage accounting, not a performance SLO or capacity gate.

    Capture before-prime, steady/load, drain and recovery bookends separately. For each load point report configured and issued rates, latency p50/p95/p99/max by shape, write-to-durable/output/client stage tails, freshness age, pending tenant and job counts, final fixed-target catchup and observation deadlines. Publish CPU/quota/throttling per role, RSS/cgroup usage, database time and statements per unit, lock-wait sampling and its limits, WAL retention, storage/network and generator/observer CPU/RSS/query/byte/time cost. Missing counters stay UNMEASURED. Do not average away a growing backlog or hide a failed authority/clinical oracle behind a successful reduction. A quiet matched comparison needs comparable source, workload/history and placement; shared-node diagnostics retain contention.

    Next load ladder and unmeasured limits¶

    1. Commission two tenants with access, stored, selected clinical and stock-frame controls. Run small with the released runtime input and independently reduce it. Any missing essential oracle keeps its dependent claim UNMEASURED.
    2. On the same attributed source/history, admit representative-mix; extend observation to a known due-work opportunity plus drain if the finite window permits. Do not invent a clinical latency or availability target.
    3. Step ordinary REST at 1, 2, 5 and 10 requests/s with fixed viewers, probe cadence and resources. Use stress-discovery separately to vary probe cost. Record saturation/refusal/drop/backlog curves as results; do not promote capacity from the last nominally issued rate.
    4. Vary connected viewers, hot/cold skew, provisioned-vs-active population, retained history and reconnect burst independently after their instrument boundaries exist. T currently fixes equal weights and one full roster. No such missing dimension is silently implemented by these profiles.
    5. The existing operating owner can explore 1,000/3,000/10,000 tenants on admitted resources with realistic cadence and source-qualified all-writer progress. These cluster profiles grant none of that headroom or other experiment budget.

    Test shards are independent test-state Jobs; independent fixtures have independent state; load workers divide one declared offered workload; API/evaluator/realtime horizontal scale-out changes runtime topology. One cohort Pod remains one replica. Neither test fan-out nor extra clients proves application scale-out. Backing-store Pod replacement on emptyDir loses state and cannot qualify durable recovery. Role restart, recovery without a new write, independent-tenant continuity, alarm/due work, connector catchup, large histories, long endurance, HA and production admission retain their own unmeasured boundaries.

    Populated clinical history¶

    To compare with a populated entries window, choose one five-minute UTC boundary for the whole pair. Apply it to each existing rate profile before preparing either binding. For example, in Bash:

    history_anchor_ms=$(( $(date -u +%s) / 300 * 300000 ))
python3 tools/mt-bench/kubernetes/workloads/profile.py populate "$profile_90" "$history_anchor_ms" "$out90"
python3 tools/mt-bench/kubernetes/workloads/profile.py populate "$profile_120" "$history_anchor_ms" "$out120"

    The command changes only history. Supply the derived file to the standard Kubernetes case or put its history object in the Compose runner configuration. The shared toolchain projects it onto both platforms. The existing existing-provisioner-only profiles retain zero extra rows.

    synthetic-sgv-6h-v1 writes 72 synthetic SGVs per provisioned tenant using its own DATA credential and the ordinary v1 entries endpoint. Samples occur every five minutes, with the newest at the selected anchor. A deterministic tenant-specific series populates the entries side of the clinical working set. Treatment, device-status and profile history retain the standard seed. The fixture device uses underscores, which keep it distinct from ordinary and probe run markers.

    Use a separate fixture per binding when deployments require different credentials or topology. Kubernetes fixture seed cases write and read back history before writer quiescence and snapshot. Kubernetes checks the selected recipe on restore. Both platforms verify populated restores through PostgreSQL before traffic. New disposable runs seed through DATA. A lost acknowledgement can be retried from a complete or absent tenant. A partial or changed tenant requires a fresh fixture. An overlapping provisioner or ordinary SGV upsert key also refuses seed.

    The run's populated-history.json records the anchor and observed age, eligible rows, actual pg_column_size(doc) bytes per tenant, a logical digest and the number of batches seeded in this phase. This byte measure excludes indexes, tuple headers and WAL. Match the logical digest across arms. The comparison uses synthetic host order and authored entry fields so database-generated metadata can differ. A finite arm requires all its rows to remain visible in the 48-hour cold entries window through its work deadline. Choose a new shared anchor and fresh fixtures if the pair ages out. Physical footprint, ordinary request count, acknowledgement latency and clinical completion remain measurements for the selected candidate.
