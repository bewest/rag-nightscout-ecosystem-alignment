    Reuse the canonical local runner¶

    Living document, last changed 2026-11-18 at c22139bfb.

    runner.py replaces copied per-attempt preparation and execution scripts with one configuration and the existing adapter.py entrypoints. It does not build an image, allocate a remote host or grant capacity acceptance.

    For new runs on this workstation, use the overflow-disk storage layout in AGENTS.md. Keep helpers under the appropriate /mnt/data/nightscout-workspace/worktrees/ directory and select outputs under /mnt/data/nightscout-workspace/artifacts/<lane>/<run>. The directory arguments below are explicit storage choices, not automatic runner defaults. A missing or unwritable /mnt/data is a storage error; do not fall back to the home drive. Existing runs and their original guards keep their current paths.

    Copy the small rehearsal profile to private storage. Set its verified helper head, repository paths, existing diagnostic receipt, new project and unused explicit CIDRs. The receipt still binds the source pair, image, instrument and traffic duration through the adapter's existing contract. Reusing a qualified app/image does not require rebuilding that image or running application acceptance for a tenant/RPS change.

    For new configurations, run python3 -B tools/mt-bench/m7-joined/runner.py identity from the committed helper, then replace helperHead in the configuration with the returned helperInstrument field. Choose exactly one pin. Content pinning permits the same executed bytes at another commit; the adapter still records the actual commit. Markdown documentation is excluded from the instrument digest. Changed executable/configuration inputs remain pinned and dirty inputs refuse. Existing helperHead configurations keep their exact-commit behavior. This new manifest definition applies only to new captures; old runs keep their original helper, receipts and attribution. Do not change helpers under a live guard.

    The adapter preflight still checks required source/runtime and instrument paths. Optional realtime cost-counter gaps are saved in preflight-observations.json as NO-INSTRUMENT; they do not ban discovery traffic or become measured zeros. These counter observations grant no acceptance. Shared-host discovery already records contention without requiring other agents to stop their containers.

    python3 -B tools/mt-bench/m7-joined/runner.py prepare \
  /absolute/private/run.json /mnt/data/nightscout-workspace/artifacts/example-lane/run01
python3 -B tools/mt-bench/m7-joined/runner.py rehearse \
  /mnt/data/nightscout-workspace/artifacts/example-lane/run01
python3 -B tools/mt-bench/m7-joined/runner.py result \
  /mnt/data/nightscout-workspace/artifacts/example-lane/run01

    Use the qualified Node/npm paths in PATH. prepare stages canonical source, configuration, probe, workload and owned dependencies. It starts no services. rehearse performs canonical deploy, real instrument preflight, a generated program failure control, ordinary tiny traffic, collection, reduction and cleanup. The control omits the required probe URL, checks Node's actual ERR_INVALID_URL refusal before network I/O, then the normal caller runs the same unmodified generated bytes. execute runs the same path without that intentional refusal. Neither action retries a phase.

    The example uses two synthetic tenants, four stock clients, serial JWT setup and 1 offered scenario request/s. Its work window is finite; its independent guard stops an active stage and invokes the adapter's owned-project cleanup at the deadline. The runner checks process birth and group before escalating a stage that ignores TERM. Normal completion also cleans up. Explicit cleanup is:

    python3 -B tools/mt-bench/m7-joined/runner.py down /mnt/data/nightscout-workspace/artifacts/example-lane/run01

    Keep the helper source fixed while a run or its guard is live. Cleanup retains the adapter's ownership and source checks. It never stops peer services. result.json records the phase, native adapter status, traffic phase, process failures and cleanup outcome. Native summaries, readiness, recent role logs and collector outputs remain private artifacts. A missing scenario counter stays unknown; zero scenario attempts with HTTP setup exchanges is setup-only data. COMPLETED_PARTIAL means the pipeline returned with a partial adapter result; it is not a successful application or capacity claim.

Ordinary five-minute probe cadence remains the default; comparisons that select a shorter cadence must record it.     Remote calibration keeps its existing strict default and exact source/image presets. Changing load does not extend source/image/deadline or budget authority, and does not alter an already entered run.

    Compose and native Kubernetes discovery resolve positive roster sizes and hot weights within the generated JavaScript arrays' combined length limit. Source/image identity and fixed acceptance profiles stay exact. Each experiment keeps its selected source/image tuple and its own receipts.

    The actual public probe accounting helper is exported with a hash and checked before driver installation. It records admitted, accepted, uncertain, refused and pending writes without SQL or provider authority. The existing collector retains its ledger and generator process results alongside probe/fanout/k6 artifacts. Source/ownership mismatches, observed wrong data, clinical failures and invalid metadata still fail. Strict reporting retains its original full-client, zero-failure and required-metric checks. REST metrics, sampled client frame times and SUT completion observations remain separate; remote output timing is UNMEASURED and no cross-host clock subtraction is used.

    Finite experiment batches¶

    runner.py batch-plan <batch.json> --payload-root <absolute-private-directory> prints a deterministic review plan without starting services. batch-run <batch.json> <new-private-output> --payload-root <absolute-private-directory> executes that same admitted specification. batch-result <private-output> reads completed and partial per-cell results, including after an interrupted batch. The ordinary single-point commands and their defaults stay available.

    Before copying a cell's resource fields, run:

    python3 -B tools/mt-bench/m7-joined/runner.py batch-resources /absolute/private/run.json

    This validates the ordinary runner configuration and prints resources plus the allocation breakdown without starting actors. Copy resources to the cell and set the batch envelope for the desired concurrency. Then batch-plan checks the complete payload, workload, isolation and aggregate bounds. These commands grant no infrastructure or spending authority.

    Start from the local batch template. Replace its source/helper/receipt paths and hashes, project/CIDRs and zero cleanup cutoff with the reviewed inputs and original absolute cutoff; the template is inert. Both cells reuse the same immutable source/image/helper. The template declares room for two whole cells. Set its aggregate envelope to the resources allocated to your lane; a smaller envelope queues cells without reducing their quotas.

    Batch digests use the shared canonical vectors. Numbers must be finite; integral numbers must fit the exact shared range −9007199254740991 through 9007199254740991. Negative zero becomes zero, and 1.0 and 1 have one identity. Payload bytes are never transformed.

    The common version 1 batch structure is shared with the deployment controller's pgstream-caller.mjs batch API. A batch contains explicit cells; expand an R&D matrix into cells before review rather than submitting executable generators. Each cell.config is an ordinary runner configuration locally, or an existing remote caller specification remotely. Local and remote batches have the same review fields; each backend still checks its own typed runtime contract.

    For local cells, target is {"kind":"local"}, ports are empty (no host-port configuration is supported by this runner), and subnets exactly match the configuration's backend and edge CIDRs. Names and CIDRs cannot overlap another cell, even when cells run sequentially. The existing adapter performs its fresh host census before effects. Local cells use any existing named diagnostic profile or an explicit diagnostic-resource-allocation, with the same adapter selection and topology checks as a direct run. A cell must reserve at least the selected CPU/memory ceiling, host V8 heaps and managed-resource allowance. Larger authored reservations are valid; the batch envelope remains the aggregate bound. An explicit allocation supplies its own driver limits and is not capped by the old local reference reservation.

    Named profiles retain their server limits, while discovery replaces their old 500-millicpu/1-GiB k6 default with the existing 2000-millicpu/4-GiB driver. The planner includes that delta. For example, the named 4-CPU/8-GiB profile requires 5500 millicpus and 11811160064 memory bytes for the complete discovery cell, plus 1024 MiB host V8 heaps, zero money and a conservative 64 managed resources. Use batch-resources for the selected configuration instead of repeating this arithmetic. Profile names describe their original reference allocation.

    The allocation breakdown uses the selected ceiling as a conservative upper bound for SUT roles and declared oneoffs; it does not claim they consume that amount simultaneously. Host heaps include helper, generator and probe overlaps. Host RSS/native memory remains separately observed; a V8 heap limit does not bound RSS. The caller keeps the aggregate envelope within its lane allocation. Concurrent cells share the host: record contention in comparisons. The scheduler accounts declared maxima; it does not reserve a quiet machine, establish physical CPU demand or bound host RSS. Phase-specific lower reservations require matching producer enforcement and focused controls.

    Each batch holds the original UID-global driver lock and atomically reserves whole cells in a private ledger. Only a live exact-birth coordinator and matching nonce can authorize a child driver to use its own cell heap lock. This retains legacy-driver exclusion, per-cell native quota/census checks and stale-marker refusal. It does not rename the global lock to pretend aggregate admission. The unchanged independent guard owns each cell's finite cleanup window, starting with preparation; the batch cutoff never extends it. Source-loader preflight now runs automatically during batch preparation before services. A failed cell keeps its private phase and partial outputs. Admission continues for independent cells when their reservations fit. Unconfirmed cleanup retains its entire reservation. A child rechecks the ticket's absolute cleanup cutoff before preparation, so process-launch delay cannot silently authorize a fresh full window. Coordinator death leaves custody markers intact for explicit exact-resource reconciliation; PID expiry alone never frees resources.

    SIGINT/SIGTERM stops new admissions while entered cells finish their original finite cleanup. Reservations release only after the child returns, the original guard is absent, adapter cleanup records exact absence and the cell heap marker is empty under exclusive lock. No other cell's reservation or resource is released. Changing payload bytes or source/image/helper pins refuses before a new cell starts. Raw logs, tickets, namespaces, process births and ledgers stay in ignored private output, not the public repository.

    Local batch configurations use existing tenant/rate/duration/cadence/hot-factor options and preserve the adapter's required correctness oracles. Ordinary local batches currently require an empty fault allowlist; unsupported fault cases refuse. Remote component cases retain their existing typed implementation. Optional counters and generator headroom remain UNMEASURED when unavailable. A constrained generator can limit offered load; that is not a product capacity measurement. Every batch result keeps capacityAcceptance: NOT_GRANTED. Parameter changes inside the declared envelope use the same tool and focused input checks; they do not trigger an application rebuild or full acceptance.

    A reviewable batch plan does not grant remote spending, export or tool permission. Remote plans must disclose their payload allowlist and exact provider destinations and use the existing authoritative budget/custody hooks. Paid allocation and transport remain with the remote owner. Independent remote pairs retain exact unconditional deletion; retaining a pair across cells is a separate reset and rig-ownership capability. Active experiments stay pinned to their original tools.

    Scheduling checks use the real local caller/process/ticket/flock path with synthetic prepare/execute actors, and the remote caller with synthetic root hooks. They qualify admission, overlap, failure isolation and custody, not application capacity or a native live provider gateway. Remote batches reuse verified sealed input directories; batch-run does not call bundle or export images again. Changed inputs require their own matching source/image/helper pins and hashes. Remote cleanup uncertainty retains accounting while other eligible pairs proceed; reservation/authority uncertainty stops admission. Per-cell deadlines skip only the expired cell; the common cutoff leaves no cell eligible. Native approval message lookup/provider installation remains UNMEASURED here and belongs to the remote custodian; source adapters do not grant tool permissions.

They do not by themselves qualify native Vault overlap; that requires retained source-bound native actors, progress and independent exact cleanup evidence.

    Resolve once for local and remote discovery¶

    The existing version-1 runner JSON remains the authoring source. prepare holds workload and source options; workSeconds and cleanupSeconds bound the finite window in seconds. runner.py project resolves adapter defaults and produces the configuration digest, receipt limits and a draft version-2 diagnostic receipt. The command creates no run and grants no execution or provider authority.

    python3 -B tools/mt-bench/m7-joined/runner.py project /absolute/private/run.json
python3 -B tools/mt-bench/m7-joined/runner.py project /absolute/private/run.json \
  --source-acceptance /absolute/private/source-acceptance.json \
  --remote-overlay /absolute/private/remote-overlay.json

    The optional source-acceptance document is exactly {"status":"PENDING"} or {"status":"PASS","reference":"/absolute/private/acceptance.json","sha256":"…"}. PASS requires the referenced file's actual SHA-256 and a joined-acceptance PASS record matching the exact core/deploy pair and image. The evidence record must also identify its own instrument and evidence digest. The acceptance instrument can differ from the experiment helper. A missing, changed or mismatched record refuses. This validates the retained record, not a new application campaign. The resource owner issues genuine authorization from the draft only within existing authority; changing DRAFT to AUTHORIZED_DIAGNOSTIC is an attestation, not a permission bypass. Keep historical receipts and captures unchanged.

    Version 2 requires purpose: BOUNDED_DISCOVERY, the generated configurationSha256, execution, limits, sourceAcceptance, and matching functionalAcceptanceAtAuthorization. It binds source/image/helper, PostgreSQL image, tenants, cadence, viewers, concurrency, topology, selected resource profile, completion reader, k6 image and work/cleanup limits. The runner refuses altered mirrors before output creation or guard arming. Adapter admission checks source/image/receipt before dependency preparation, checks actual project and CIDR availability before staging, and rechecks prepared semantic input before deploy/run. Actual image labels, generated plans, dependency bytes, quotas, process births, ownership, free ports and runtime census remain independent readbacks. Namespace readback is an observation, not a reservation.

    Legacy version-1 discovery receipts retain their PENDING-only semantics and UNACCEPTED result attribution. Version-2 results record PENDING or PASS truthfully, with the source-acceptance reference and configuration digest. Every discovery result still carries capacityAcceptance: NOT_GRANTED; accepted-source diagnosis cannot promote capacity or release claims. The proof owner's recovery classifier retains failed correctness episodes and dependent UNMEASURED claims. Strict acceptance remains separate and failed correctness remains failed.

    Tenant roster and topology The source limits tenant count. The generated roster and hot wheel must fit JavaScript arrays. Compose discovery supports 1–16 API replicas and 1–8 evaluator/realtime workers with the required source and role receipts. Native Kubernetes runs one API and one evaluator/realtime worker with an external producer.

    offered-rps Positive finite scenario HTTP attempts per second with a representable k6 time unit. Setup and stock-probe requests have separate rates.
    warmup-seconds, idle-seconds, load-seconds, setup and drain Positive integer seconds within the shared duration representation. A finite work window must contain the applicable phases.
