    Running the cgm-remote-monitor suite for T1.2¶

    Living document, last changed 2026-09-14 at 43f309f2.

    Four things block a clean run on this machine and none of them is obvious from the repo. Recorded so the next person (or agent) does not rediscover them.

    Worktree: externals/work/crm-seam, branch seam/t1-2-storage-interface, based on origin/chore/nightscout-modernization @ 0a4109f6 (decision D9).

    1. The branch refuses this host's Node¶

    engines requires ^22.23.2 || ^24.20.0; the host has v24.15.0, and the server exits with ERROR: Node v24.15.0 is not supported rather than degrading. The suite therefore runs inside node:24-bookworm (24.21.0) via run-crm-tests.sh. node_modules contains no native builds, so the host's npm ci output is reusable inside the container.

    2. --network host is required, not convenient¶

    tests/fixtures/http-assets/worker.js:57 asserts the database is on loopback. A bridged container IP fails three tests for an unrelated reason.

    3. Use a STANDALONE mongod, not a replica set¶

    A single-node replica set advertises itself as 127.0.0.1:27017. Under --network host that address resolves to whatever mongod the host already runs (here, a system 3.6.8), and connections churn and drop. The suite needs no transactions or change streams, so standalone avoids the topology entirely.

    Port 27018, because the host already has something on 27017.

    4. Raise nofile, or mongod fatal-asserts mid-run¶

    Docker's default 1024 file descriptors is not enough for the collections and indexes the suite creates: WiredTiger hits Too many open files inside __wt_open and mongod takes a fassert() — an abort of the whole server, not a failed test. This is the same failure EXP-MT-040b measured at 50 tenant databases, reached here by an ordinary test run.

    docker run -d --name nstest-mongo --ulimit nofile=64000:64000 -p 27018:27017 mongo:7

    Putting it together¶

    docker run -d --name nstest-mongo --ulimit nofile=64000:64000 -p 27018:27017 mongo:7
cd externals/work/crm-seam
npm ci
printf 'CUSTOMCONNSTR_mongo=mongodb://127.0.0.1:27018/testdb\n' > my.test.env
tail -n +2 tests/ci.test.env >> my.test.env     # my.test.env is gitignored
../../../tools/seam/run-crm-tests.sh './tests/*.test.js'

    Baseline on this branch: 2150 passing, 1 pending, 0 failing. That is the number every T1.2 increment has to reproduce.
