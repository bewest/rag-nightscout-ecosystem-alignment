## Join questions (ranked)

**Data stops arriving**
1. **S15 and S1/S2, CGM-from-Nightscout.** This is the only Trio request whose failure would silently stop glucose feeding the algorithm: `GET entries/sgv.json?count=1600&find[dateString][$gte]=<ISO>`, where an error gives `[]` and nothing is shown. The join must confirm this exact shape still returns 200 on 15.0.9 (with #8754 and #8758): `count` of `1600`, a `dateString` string filter, and no top-level `date` filter.
2. **S15, uploads.** Any new 400 on a treatments, entries or devicestatus POST would make that pipeline retry forever, invisibly, with data kept only on the phone. Does anything in the candidate newly refuse a v1 POST body that has a plain `id` (upper-case UUID) field, an `enteredBy` of `Trio`, `created_at` with fractional seconds, or (on devicestatus) no `created_at` and no `_id`?
3. **S12.** `find[eventType]=Temporary+Target`, a literal `+`: does the candidate still decode `+` as a space in v1 query values? If not, the temp-target fetch returns `[]` and followers' temp targets stop importing.

**Wrong numbers**

4. **S11.** The new COB display takes Trio's `openaps.suggested.COB` or `openaps.enacted.COB`, dated by `timestamp`. When automation is off, Trio omits `enacted`. The join must confirm the selector dates Trio's `suggested.timestamp` (a Swift ISO date string) correctly, so the fresher block wins.
5. **S8.** The override-run DELETE by `created_at $eq` plus `eventType $eq Exercise`, followed by a re-POST: is it unaffected by the operator allowlist and the `$eq`/date rewriting? If it is refused, the run is never re-posted (the batch throws before the POST), and Nightscout keeps the placeholder duration.

**Cosmetic / low**

6. **S10.** Profile POST with no `_id` inserts a new document on every settings change, and Trio accepts only status 200. Is any profile POST status or field filtering changed (for example stripping the remote-control fields `deviceToken` or `overridePresets` that followers depend on)?
7. **S5.** Token-only sites cannot use Trio (it has only the API secret, and the URL query is dropped). This is not new in 15.0.9, but worth one line in any "check your apps" guidance for `AUTH_DEFAULT_ROLES=denied`.
