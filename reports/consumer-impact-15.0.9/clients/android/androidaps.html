    The main structural fact: dev removes the v1 (socket.io authorize/dbAdd) client¶

    • master ships two Nightscout clients:
    • NSClient v1: plugins/sync/.../nsclient/, socket.io only. Uploads go through dbAdd/dbUpdate.
    • NSClient v3: plugins/sync/.../nsclientV3/ plus core/nssdk. REST /api/v3/* over Retrofit, plus the /storage and /alarm socket namespaces.
    • dev keeps only v3. Commit 30fe4591a7 (2026-05-27, "Eliminate NSCv1", 101 files, −4167 lines) removes the v1 plugin. git merge-base --is-ancestor confirms it is on dev and not on master. On dev:
    • git grep -n -E 'NSClientService|"dbAdd"|"loadRetro"|"authorize"' over non-test Kotlin finds no v1 socket code.
    • dev also moves to Kotlin Multiplatform: Retrofit is replaced by Ktor (NightscoutApi.kt), and there is an iOS client on socket.io-client-swift.
    • Consequence for the join. Every S6 main-namespace hit below (authorize, dbAdd, dbUpdate, main-namespace ack) exists only in the shipping 3.4.x line. It stops mattering once users move to the 4.0 line. 3.4.x users who picked NSClient v1 stay on the v1 socket path until they upgrade.

    S6 websocket Library: io.socket:socket.io-client 2.1.2 on both refs (master gradle/libs.versions.toml:164, dev :194). The 2.x Java client speaks the Socket.IO v3/v4 protocol (EIO=4); that comes from the library's compatibility line and is not verified in-repo. The server is socket.io ~4.8.3 with allowEIO3: true on every ref, so EIO3 support is not needed. v1 main namespace (master only): connect, then authorize (above), then listen for dataUpdate, announcement, alarm, urgent_alarm, clear_alarm. It emits dbAdd, dbUpdate, and ack(level, group, silenceTime) on the main namespace. It never sends loadRetro or dbRemove. On an authorize failure: the server (every ref) calls socket.disconnect() without replying, so AAPS receives only a disconnect event. The watchdog pauses NSClient for 15 min and raises an URGENT "NS malfunction" notification after 5 connects in 2 min. A dbAdd reply of {result:"Not…"} triggers EventNSClientRestart (reconnect). With AUTH_DEFAULT_ROLES=denied: a correct API_SECRET gets admin rights, so dataUpdate and writes are unaffected. The candidate's new gate (loadRetro refused for sockets without read) does not touch AAPS, because AAPS never calls loadRetro. v1 main-namespace ack has no server handler on any ref: git grep "'ack'" over lib/server/websocket.js finds nothing on 92d08342 or ef3404fd; the only ack handlers are in lib/api3/alarmSocket.js. So AAPS v1 alarm silencing is already a no-op on 15.0.8. This is pre-existing, not a regression. v3 (both refs): two sockets, <url>/storage and <url>/alarm. Each sends subscribe {accessToken}, and storage also sends collections:["devicestatus","entries","profile","treatments","foods","settings"]. foods is not the server collection name food; that is pre-existing. On /alarm it emits ack(level, group, ms). Candidate change that reaches v3: /alarm now sends alarms only to sockets in AlarmReceivers, which requires api:*:read. ack is now silently dropped unless the token has notifications:*:ack (alarmSocket.js@ef3404fd:141-153). A token with a role lacking either permission would stop receiving Nightscout alarms in AAPS, or its snooze would stop reaching Nightscout, with no error returned.     Things not analysed, and why¶

    • Whether a released 3.4.x build and master 598e2eb39c differ on these paths. Only origin/master (= tag 3.4.2.6) was read; older 3.x tags were not diffed.
    • The EIO version comes from the library's major version, not from resolving the dependency tree. No build was run.
    • iOS and desktop (dev): only noted, not analysed. They use the same NsConnectHandler payloads through socket.io-client-swift and Ktor.
