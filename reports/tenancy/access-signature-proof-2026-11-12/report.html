    Living document, last changed 2026-11-11 at b26908682.

    Capability and fixed resource boundary¶

    Only successful Ed25519 mathematical proofs are reused. Every call still resolves its current trusted key descriptor and checks issuer/audience/purpose, current FIPS mode, tenant, claims and expiry. Every authentication still obtains current DB authority. No credential decision, grants, claim acceptance or negative result is cached. There is no TTL/grace/revocation policy change.

    A proof matches exact signed bytes and signature plus the current public material. The identical immutable native KeyObject has the identical material. A different object must match exact public DER before any reuse. A new object under the same kid with changed material performs fresh crypto and refuses the old signature. DER work occurs only on a potential hit across different objects, avoiding unconditional encoding cost on cold misses.

    One process-wide LRU has at most 256 positive entries, one MiB of ASCII encoded proof keys and optional DER, and 16 KiB per entry. Native public-key references are bounded by that same entry count; there is no per-tenant cache or separate encoding LRU. Larger inputs stay uncached. Encoded byte accounting is not a claim about V8 object overhead, native heap or process RSS.

    The new unit suite's eight cases establish reduced repeated crypto work while current key resolution and authority snapshots still run for sequential and concurrent attempts. It primes a valid proof, then refuses corrupted signatures, changed signed bytes, removed keys, changed purpose, same-kid changed material, wrong tenant, expiry and revoked current authority. Lookup-only expiry semantics do not carry into ordinary verification. Different objects with identical DER can reuse the proof; changed DER cannot. A controlled FIPS-mode discriminator forces fresh math work; no live FIPS deployment acceptance is claimed.

    The entry-bound control makes an evicted proof perform crypto again. The byte control reaches the encoded budget before the entry count, then independently checks oversized proofs stay uncached. Owned scratch removes each limit in turn: entry ablation goes red at 257 !== 258, byte ablation at 140 !== 141. Replacing the full proof key with a constant accepts a corrupted signature and makes the expected TOKEN_SIGNATURE assertion go red with Missing expected exception. Working source and peer worktrees are never mutated by controls.

    Native tests use uniquely owned PostgreSQL/Vault and actual API CLI processes, current management-token authority and private lifecycle transports. Current revocation, wrong-tenant denial, expiry, key policy, cross-replica grants and response/restore lifetimes remain green. Non-API lifecycle peers remain synthetic status/invalidation participants. All owned resources are cleaned. These are focused capability checks, not a full all-role deployment campaign.

    Substantive intermediate failures¶

    An eager-DER prototype added visible cold-churn work in exploratory measurements. It was not adopted; the final implementation defers DER until needed. That transient implementation was not committed or execution-hash pinned, so its local diagnostic timings are not accepted comparison evidence. They remain in the evolving local handoff. Final before/after captures above have exact source and instrument attribution.

    The first broad focused run produced 78 passes and two strict bootstrap reset fixture failures. Investigation corrected an initial hypothesis: the actual cause was valid compact FK syntax in management issuance DDL, while the fixture required whitespace before the parenthesis. The coordinator repaired the closed FK grammar and explicit reset-table closure in original commit 55e875161a95a8ab1e60b751e29515fee92dd70c, with its own red control. That repair was merged before the final native and focused checks. No immutable migration, RLS or runtime authority guard was weakened.

    Integration boundary¶

    The coordinator owns original-history integration and the final coherent full/browser/enabled-corpus and capacity acceptance. Those campaigns remain UNMEASURED in this lane. This local math result must not be attributed to the unchanged legacy/Vault path or used as whole-authorization capacity evidence. The isolated alignment evidence checkout retains its already-reported missing external gate-worktree prerequisite; no queue state or gate was changed to manufacture programme acceptance.
