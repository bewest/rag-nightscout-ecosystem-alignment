    D6 metadata reader and consumer signalling — focused acceptance¶

    Living document, last changed 2026-11-11 at 5cd4dde81.

    Contributor-facing measurement record, captured 2026-11-11 (America/Los_Angeles). Synthetic fixtures only. This records focused local capability evidence; capacity, joined programme acceptance and deployment qualification remain separate.

    The optional D6 source is implemented on core 419af9b1f6dd59d0000f113a886db51fa4fdc6d1, branch codex/d6-reader-capability-20261112. Original history contains implementation a24f741c, merge 51e09ea1 of coordinator f3a18445, then the native/watchdog repair. The merged source retains registry step A and authorization changes. Source contract: core docs/d6-change-feed.md; deployment helper: lib/change-feed/postgres.provision.

    Implemented boundary¶

    • Dedicated multitenant feed-reader role, outside serving processes and tenant operation cohorts. An EXECUTE-only non-replication login calls fixed-slot wrappers owned by an exact NOLOGIN/NOSUPERUSER/NOBYPASSRLS/REPLICATION identity.
    • Reviewed operational function catalogue, pinned for restore census. Wrapper body, owner, result/security/config/grants, publication table/filter/DML shape, slot and finite resource settings are checked. NULL numeric arguments refuse.
    • Metadata-only pgoutput decoder for the write clock and activity table. Complete committed transactions produce coalesced tenant hints. Notification commit precedes slot acknowledgement; unsafe/oversize/incomplete batches do not acknowledge.
    • SQL-session loss reconnects with the same safety checks. LISTEN commits before reconciliation. Reader/listener loss and new generation enter visible degraded recovery. Healthy and degraded recovery both use fixed page budgets.
    • Realtime detects the hinted tenants, with separate bounded cold/retry work. Evaluator recovery accepts a subset, retains clinical due timers and separate per-tenant evaluation-gap deadlines. Delivery recovery is paged in feed mode; active retry work uses tracked active tenants.
    • Activity hints are independent of data writes. Existing pause/suspend control semantics remain: read/socket/evaluator work stops, pause permits uploads, suspend refuses uploads, resumption reacquires. changeFeed requires an activity reader.

    Meaningful red/restored controls¶

    Machine-readable verdicts and individual logs preserve four actual source mutations in the lane's own worktree, each restored byte-for-byte:

    Mutation Observed semantic red
    Advance before notification D6_NO_ACK_BEFORE_NOTIFY: confirmed slot position moved despite a refused notification. Output.
    Disable recovery pages D6_READER_OUTAGE_BACKSTOP: persisted B update stayed absent from observed current state with reader stopped. Output.
    Suppress activity hints D6_ACTIVITY_HINT_NOT_A_DATA_WRITE: pause transition emitted no activity hint despite unchanged data clock. Output.
    Detect every tenant after one hint D6_TARGETED_HINT_ONLY: detection received A and B instead of A. Output.

    Controls executed on merge 51e09ea1 plus the working candidate later committed as 419af9b1. The four mutated implementation files match their final versions; subsequent changes concerned watchdog deadlines, documentation and extra inventory. The exact-head native and focused runs above establish the restored final state. Controls are semantic failures, not setup or permission failures.

    Preserved failures and limits¶

    Initial focused listener runs hit sandbox EPERM; the restored focused run above had listener/subprocess access. Initial native instrumentation omitted the startup statement timeout from its raw-client control, so the first test stopped before seeding and later cases lacked rows. That setup was repaired. The CLI readiness probe originally observed its backend before shutdown handlers were installed; source now emits feed-reader started only after the handlers are present.

    The earlier native discriminator remains the source for transaction-sized SQL overshoot. Wrapper message/byte limits are post-decode. Spill settings, finite retained WAL, server statement timeout and reader RSS soft refusal are distinct limits; none establishes a hard total shared-server RSS guarantee. An oversized transaction can hold the reader degraded until explicit operator recovery. There is no silent skip/reset.

    UNMEASURED: 1k/3k latency/cost on the joined deployment, capacity, real clinical alarm equivalence under D6, full restore/epoch campaign with a live reader, sustained WAL-loss/retention fault campaign, shared-server resource envelope and deployment cgroup qualification. Existing focused clinical/authority tests passed within their fixture scope. Root owns deployment binding and final frozen-candidate campaign.

    The normal page sweep must be sized consistently with the existing evaluation-gap alert deadline. Derived scheduling examples at 1-second intervals: 3k/64 requires 47 intervals; 10k/64 requires 157; 10k/256 requires 40. These are arithmetic queue coverage bounds, not end-to-end latency measurements. Do not weaken the clinical watchdog to hide slow recovery.
