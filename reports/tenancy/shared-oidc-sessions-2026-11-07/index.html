    Capability and contract repair¶

    The common adapter uses pinned openid-client and jose, authorization code/S256 PKCE, state/nonce, explicit ID-token signature verification, issuer/audience, authentication time and exact expiry checks. Provider assertions identify a person; current local authority supplies permissions. Renewal requires provider proof and preserves management authentication, idle and absolute clocks. Successful qualifying foreground management operations alone advance idle; sensitive operations additionally require current authentication freshness.

    The initial opaque-access prototype violated the existing asymmetric contract. That read-derived audit finding was confirmed independently and repaired without changing policy. Current human access uses actual Ed25519 ns-access+jwt, explicit NS issuer/data/management audiences and provisioned purpose/tenant-bound public keys. Persisted hashes are secondary issuance bindings. Existing default/multitenant verification remains UUID-strict; the closed single-human profile accepts exactly single, separate from clinical storage's unchanged single scope. A distinct bound 64-byte Vault Transit signer performs issuance; the existing 32-byte legacy HMAC API is unchanged. Verification uses local public keys and current store authority, without a Vault verification call or expiry grace.

    Single Mongo uses one privately provisioned site authority aggregate containing global current keys, human mappings/grants and sessions. Bounded atomic CAS retries re-read all current state; a superseded or uncertain write returns no signed result. PostgreSQL uses additive forced-RLS session/identity tables and current existing tenant/credential/grant/management-actor/accepted-key state. Session-row transactions serialize logout and renewal; serving does not migrate or acquire key-update privileges. Native behavior, capacity and standalone-Mongo performance remain unmeasured.

    Both modes consume login/callback/renew/logout/session HTTP routes, Secure and HttpOnly cookie default, direct bearer, separate data/management cookies and state-bound concurrent flow cookies. Current authorization is consumed per HTTP operation and stream delivery. Recognized human failures cannot fall through to headless authentication. The existing browser sign-in dialog consumes provider login and renewal; human mode suppresses dormant legacy credentials. Sign Out forgets this browser's legacy material, commits local revocation, clears its cookie, then follows the configured provider logout endpoint when available. Unconfirmed local revocation remains visible and never becomes a success reload. Default-off single behavior and headless authentication retain separate paths.
