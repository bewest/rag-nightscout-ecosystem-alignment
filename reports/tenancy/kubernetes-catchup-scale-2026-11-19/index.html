    Kubernetes fixed-target collector scaling¶

    Living document, last changed 2026-11-18 at e54cdeead.

    Fixed on a local branch; Kubernetes runtime qualification remains UNMEASURED. This is a reproduced local observer experiment on frozen helper base 2b05da9dd0dac2c80d49518d4ceb9e931521fca8, with the collector/query changes in this record's commit. The application and native input codec are unchanged. The retained evidence identifier is kubernetes-capacity-20261118/catchup-scale/sql01; raw rows and the receipt stay outside Git. Source acceptance stays PENDING and capacity NOT_GRANTED. The retained receipt SHA256 is 7d8ea761142616aa04f55b7f98418fb37ea70d0986265c3728b348d0662c56c1.

    The collector previously issued one PostgreSQL exec per 64 tenants. It now issues one all-roster progress SELECT inside the existing read-only transaction, with the same owned-namespace and source/incarnation checks before and after. The progress-only transport removes repeated constant reader metadata and JSON field names. Its decoder restores every independently checked typed/state field before calling the unchanged strict completed-oracle.progressSnapshot. Clinical SELECTs, native source validation and the fixed-target assess function are unchanged. Runtime inspection still covers every tenant in 128-tenant pages.

    The whole round is now inside the selected round deadline, including inspection and final census. Child SQL/exec timeouts receive the remaining time, SQL gets a finite statement timeout, and the inspection helper's paging clock uses that remaining round rather than its ordinary 15-second default. drainObservation is a supported typed workload field. Its new sqlMaxBytes setting defaults to 16 MiB per round and can be selected explicitly alongside the existing total maxBytes, query, round and interval budgets. Actual SQL and inspection cost still counts against the total. Drain/work cutoffs and the clinical 120-second deadline remain independent and unchanged.

    Reproduced differential measurement¶

Declared fixture limits were 1 CPU, 1 GiB memory, a 512 MiB temporary data filesystem and a 300-second container deadline, with no host port or persistent volume. Exact-ID removal and a separate label inventory measured cleanup ABSENT. Each representation ran twice on the same fixture.     Controls and remaining integration¶

    At both populations, actual transactional mutations separately removed a tenant, changed native source identity, changed native generation, changed restore generation, corrupted the typed contract digest and removed native stream state. Both readers refused with the same code; rollback restored the exact original snapshot. A write inside BEGIN READ ONLY refused. The retained receipt contains 15 control results, including the two all-tenant assessor results.

    Focused tests also refuse missing capture, stuck tenants, foreign ownership, runtime reset, missing jobs, invalid observer selections, oversized SQL and round overrun during inspection. A selected 32 MiB SQL budget admits the synthetic 17 MiB response that the default budget refuses. Actual branch ablations make the configured-round, whole-round, storage-basis and raw-first criteria red, then restore green. The real inspection helper's default paging deadline refuses a long synthetic multi-page read; its selected remaining deadline passes, and an ablation that restores the fixed default makes that criterion red. Disposable cache generation retains the existing permissive semantics; it is distinct from runtime identity and native source generation. Existing native/due/restore assessor controls remain in the focused suite. The final focused run passed 100 Python tests across the collector, adapter, common projection, workload, shared catch-up, shared storage collector and phase-window suites, plus both native/progress Node control files. Logs are retained alongside sql01.

  --output <new-absolute-output-directory> --node <pinned-node> \
  --postgres-image sha256:74d436cb49d3398cf7b5d7b33635d43623d9e4da4b93c22db453f7d5d81181b1

    The owner of future entered Kubernetes points must integrate the helper after the current point closes, select a round budget that includes measured census and inspection cost, and run a small actual native control before a fresh larger point. No entered helper was changed. This lane ran no Kubernetes action, source application change, provider action, publication or Git push. Populations beyond the existing strict progress selector's 10,000-tenant limit were not tested.
