    Clinical equivalence¶

    Every head was traced on the 13-hour synthetic timeline (one hour lead-in + 12 h) with trace.cjs. Each cycle's full output is hashed: emitted, requested with message text, every property, and the due instant. The runs cover the deployed plugin set and all 22 plugins, a cycle every 1 s (46,801 cycles), and due mode with a 1 s and a 60 s slow timer. compare.cjs against base:

    head 6 runs
    C+D+E, B, A + total order IDENTICAL, every cycle (equivalence/compare-*.txt)

    equivalence.cjs (base vs due within a tree) prints the same verdict lines at every head as at base (deploy PASS/PASS; 22 plugins PASS alarm sets and base's pre-existing CONTENT DIFF lines). The trace harness gives each row its insertion ordinal from 7f5f518e on. Rerunning base with that harness gives identical traces.

    Tie order (decision view-reads-total-order)¶

    Read lab at 745c7f4e (runs/read-lab-total-order.txt) covers 17 views-equality scenarios × 4 instants, a typed-twin/tie set, 12 views-replay timelines every 2 h, and 7 corpus sets × 3 instants: 498 view instants and 5,976 reads. The ordinal is each document's position in its dataset, the order MongoDB received them in.

    measure count
    reads, in-process vs SQL with the total order 5,976 / 5,976 equal; working sets and outputs equal at 498 / 498 instants
    reads whose order differs between today's SQL and the total order (ties only; 0 differ in membership) 402: treatments {created_at:1} 242, devicestatus {created_at:-1} 126, entries {date:1} 32, entries {date:-1} limit 12 2
    of those, single-site MongoDB 7 returns the order of the total order 400, today's PostgreSQL order 0, neither 2 (the two limit-12 reads on the typed-twin set)
    mingo membership vs SQL (unbounded reads) 1,245 / 1,245 agree

    Changes against today's order, every one at an instant with a tie read (0 without one). Each comes from two or more readings with the same date:

    view field dataset instants
    properties, alarms output emitted[].clear typed-twin set (twin readings with different values) 2 + 2
    properties output bgnow.sgvs[]._id timeline twoUploaders 4

    properties, alarms working set sgvs[].mgdl typed-twin set 2 + 2

    The 13-hour timeline has no ties: its traces are identical to base with either order.

    Cost of the tie-break (runs/tiebreak-bench.txt, 288 rows, load 4.6): on the SQL path +0.2 to +0.7 ms server execution per sorted read (entries 0.80 → 1.12, device status 1.28 → 2.01, newest 12 1.11 → 1.33 ms). The in-process read takes 0.11–0.30 ms per read in total. No index applies: the read sorts its recordset in memory.

    Superseded: the PostgreSQL 16 quicksort and bounded-heap port at 7f5f518e matched the server on 5,314 random reads and 5,976 corpus reads. A stable sort without it differed on 394 tie orders and changed output on typed twins. Records are in runs/a-port-superseded/. The port is not in the lane's final state.
