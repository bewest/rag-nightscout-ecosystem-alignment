    What changed¶

    Plane rule (lib/server/serve/listeners.js checkPlane). An internal-plane listener may bind the consumer listener's address, loopback or non-loopback, when the ports differ. Refused: every interface (acknowledged or not); the consumer listener's port on its address, checked against the consumer listener even when api is not served (overlaps(spec, consumer), so a consumer on every interface also claims its port on 127.0.0.1); a non-loopback address without ADMIN_INSECURE_BIND_ACKNOWLEDGED=true. New message: ... would share the consumer listener ...; give it a port of its own with ADMIN_PORT. The reproduced case from the decision row (HOSTNAME=127.0.0.1, admin at its default 127.0.0.1:1338) now resolves and the role listens (native suite case 1).

    Restore census (lib/server/serve/operation-cohort.js assertComplete). The actor query now also returns, per backend, clinical: whether the backend's database identity holds any privilege (direct, through any role membership, or by owning the table) on a clinical table in the protected namespaces, computed from pg_class/has_table_privilege/has_any_column_privilege in the same statement, so at census time. A backend that is not a registered participant backend is accepted only when clinical === false (counted in a new exempt field); true, null or a missing flag refuses RESTORE_COHORT_UNKNOWN_BACKEND. Participants match by PID, birth and role exactly as before.

    Clinical table catalogue: lib/tenant-lifecycle/clinical-catalogue.js CLINICAL = entries, treatments, devicestatus, profile, food, settings, activity, matched by relname inside the protected namespaces. It is the set logical-restore.js reconciles (moved there from its local HISTORY/CLINICAL sets; logical-restore now reads it). Not in it: tenant_insertion_ordinal, schema_migrations, tenant_write_clock, consumer checkpoints, outbox, alarm suppression, authorization, secrets, legacy, access (see decision question 1).

    Ownership phase (lib/tenant-lifecycle/tenant-phase.js, lib/tenant-ownership/postgres.js). tenantPhase(connection, {namespace, tenant, hold}) reads only existing control state: tenant_lifecycle_windows.phase (suspended while a restore holds the tenant), and a deletion request in tenant_lifecycle_requests that is executed or whose ceremony is not cancelled, or any ceremony row not cancelled. No window row → unprovisioned. With hold: true it first takes the tenant's window lock with pg_try_advisory_xact_lock_shared(lock_key); a restore holding it exclusively reads as held. The phase is read after the lock (READ COMMITTED), and the shared lock lasts to commit, so a restore cannot take its exclusive lock and enter its data phase under an ownership change. Ownership add, transfer, recover call it after operator authority and before row locks; not active → refused, OWNERSHIP_TENANT_INACTIVE, audited with detail.lifecycle (suspended|held|deletion|unprovisioned), no ownership row change, current owners returned. list does not check. The helper is exported for other operator verbs (activity-eligibility lane's owner pause), with phaseGrants({namespace, role}).

    Wiring: the store takes lifecycleNamespace (required, distinct from the authorization namespace); MULTITENANT_ADMIN_CONFIG ownership.lifecycleNamespace (required); the store's privilege screen adds the three control tables as SELECT-only; the contract ownership-operations.json adds OWNERSHIP_TENANT_INACTIVE to the three refused enums; the deployment plan grants <prefix>_ownership_operator USAGE on the control schema and SELECT on tenant_lifecycle_windows, tenant_lifecycle_requests, tenant_lifecycle_ceremony. No clinical grant, no operation registration, no window or ceremony write.

    Findings¶

    • reproduced: with the deployment plan's grants, the admin role's backends are accepted by the census and a tenant restore completes while it is connected; widening its grant to one clinical table makes the same restore refuse before suspension.
    • reproduced: during a restore's claim, ownership changes on that tenant refuse as held; on another tenant they apply.
    • read-derived: export has no durable lifecycle state (exportTenant is one snapshot transaction; no window, request or ceremony row). "Not exporting" is not checked; nothing was invented for it (decision question 2).
    • read-derived: a deletion request committed between the ownership transaction's phase read and its commit is not fenced (the ceremony path takes no window lock at request time).

    Decision questions¶

    1. Breadth of the census exemption. Literal to the decision: any identity without a clinical-table privilege is exempt, so a non-participant with writes on outbox, alarm suppression, checkpoints, authorization, secrets, the write clock or tenant_insertion_ordinal is now accepted (the plan's readiness identity, holding SELECT on clinical schema_migrations, also becomes exempt). Restore itself writes the clinical tables, tenant_insertion_ordinal and tenant_write_clock. Recommendation (reliability, low cost): count every table the restore writes as clinical for the census (add tenant_insertion_ordinal and tenant_write_clock), keeping the admin identity exempt. Unmeasured: whether any deployed non-participant holds those.
    2. Export. No existing state marks a tenant as exporting. Options: accept that an ownership change may land beside an export (the artifact is one consistent snapshot), or add export state (export-expiry lane's area). Recommendation: accept; the snapshot already gives a consistent artifact.
