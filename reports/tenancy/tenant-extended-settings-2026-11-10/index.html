    3. Fix¶

    lib/server/tenant-app/environment.js: a frozen catalogue EXTENDED (plugin → setting → allowed JSON types: boolean, finite number, or string up to 256 characters). Each tenant's extendedSettings is projected into a fresh object of primitives. The status route shows the projection (filteredSettings recognises the tenant's own extended object), as a single site shows its extended settings. No owner catalogue entry was added; see §6.

    Owner surface reading: the 16.0.0 decision owner-settings-projected-catalogue limits owner-writable names to the projected client keys, enable and thresholds, and "every other name is unsupported on the owner surface and refuses by name". The same row records the rest as "operator-static JSON per tenant". The fix therefore carries plugin extended settings from the operator's per-tenant configuration only. An owner display change keeps them (applySettings, presentation environment; tested).

    6. Findings and open points¶

    1. Owner editing of alert enables is not decided past the first preview. The documents settle the first preview (operator-only), so the lane did not stop. Whether timeago.enableAlerts and the other plugin alert enables should join the owner surface later is a separate question. On a single site the person who runs the site sets them, and in the multitenant preview that is the operator.
    2. The serving process ignores unknown extended keys; the evaluator refuses them. The serving path does not validate tenant settings either, so the behaviour is unchanged. An operator's typo is visible because the evaluator refuses to load.
    3. devicestatus.advanced differs between modes. A single site defaults it to true (lib/server/env.js:396). A tenant leaves it unset, so the client replaces device status on each update instead of merging (lib/client/receiveddata.js:159). The merge depends on what the tenant realtime frame sends. It is not carried here, and it is a candidate for its own item. Read-derived.
    4. Single-site quirk, not changed: ERRORCODES_URGENT=9 (a single code) becomes the number 9, which errorcodes.js:68 ignores. The tenant accepts the same number, with the same effect.
    5. Numeric settings have no bounds beyond finite. No bound is documented for them, so none was invented.
