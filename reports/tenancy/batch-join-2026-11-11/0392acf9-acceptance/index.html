    Evaluator controls under write-clock-complete (evaluator-wake.integration, actual PostgreSQL)¶

    On the joined head d48a9c2c, before the switch, three tests went red: - EV_HARD_DELETE_REEVALUATED; - EV_UNSTAMPED_UPDATE_REEVALUATED; - the delete moved the signature.

    They were red because the tests write with raw SQL (DELETE, and UPDATE of activity). Raw SQL bypasses the clock, and by the decision's contract it is not a supported write.

    The rewritten controls write through the supported path, the storage port inside the clock transaction (fixture hardDelete and updateInPlace). Each one asserts its premise first: - a hard delete moves last_stamp and makes last_delete_stamp = last_stamp; - an activity in-place update moves last_stamp only.

    Every control runs twice: per component (one clock-row read), and in batch mode (one readStamps per pass).

    control per component one read per pass
    idle: 5 passes, 5 checks, 5 unchanged, 0 cycles pass pass (stampReads 5)
    lost wake (EV_LOST_WAKE_BACKSTOP) pass pass
    hard delete re-evaluated (EV_HARD_DELETE_REEVALUATED), stamp-only pass pass
    unstamped-domain update re-evaluated (EV_UNSTAMPED_UPDATE_REEVALUATED), now stamped pass pass
    eval-cost E after a hard delete (EV_COST_E_HARD_DELETE): checkpoint and delete stamp moved, delete seen pass n/a

    Unit cases: - EV_STAMPS_ONE_READ; - EV_STAMPS_CHANGED_ACQUIRES (one write and one hard delete among three tenants); - EV_STAMPS_REFUSED_NOT_A_CHANGE; - EV_STAMPS_MISSING_ACQUIRES.
