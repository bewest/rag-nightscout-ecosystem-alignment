    Integration and compatibility¶

    The runner contract owns configuration fields, resource/file bounds and commands. The existing runner configuration accepts prepare.driver-plan as a JSON string, and its receipt projection binds the normalized plan. Changing a VU budget changes the configuration hash. Source/topology authorization remains with its existing owner. Historical trace/preallocated selectors and original reports/verdicts are intact.

    The minimal launch integration changes the adapter parser, discovery k6 launch and existing shard launcher. HTTP payload generation, status fingerprints, stored-write oracles, clinical/client boundaries and source admission are reused. Unknown executors/options, invalid windows/VUs, missing shard data and unsupported remote launches refuse explicitly. Runtime CPU/memory stay in the existing allocation. Trace limits are per file; shard count multiplies retained storage.
