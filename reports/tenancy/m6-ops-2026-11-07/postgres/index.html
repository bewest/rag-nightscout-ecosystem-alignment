    M6 operations: bounded PostgreSQL recorded evidence¶

    This bundle validates an archived synthetic SQL-core measurement: initial five cases, eleven distinct semantic failures with physical witnesses, eleven targeted restorations, and a fresh final five cases. It is RECORDED-EVIDENCE. The gate reads observations and pinned app git objects; it does not execute a database run or assert current-HEAD, whole-M6, journey/client, browser, provider or production-availability acceptance.

    The coordinator accepted the bounded SQL result with a precise offline process-audit reconciliation and an independently indexed resource-release witness. The original parent accepted:false and runtimeReleased:false remain unchanged. R73 references this accepted bounded archive, and TEN-RESOLVE declares its recorded gate. M6 remains open; the gate does not enable roles or make a release claim.

    Precise process-audit reconciliation¶

    The original driver overwrote nine live process identities with terminal Linux Z samples whose command lines were empty. All nine independently observed live probes retain exact matching PID/start/owner/group identity and source-derived Popen argv hashes. Both recorded post-child and independent current observations are absent. The other64 identities match without an exception; no missing, extra or unowned birth is admitted. Initial and final invocations each retain the exact five-birth census.

    The public representation replaces machine identifiers with stable per-stage birth aliases, a fixture-owner class and opaque identity hashes. Expected command hashes are pinned in the reviewed plan. A coordinated change to driver and independent hashes cannot authorize a different expectation. Only the nine predeclared probe records may use the Z/empty-command exception. The original error count/class and false verdict remain explicit.

    The separately indexed coordinator release witness records normal removal of one exact container and its labelled volume, all73 birth absences and restoration of the complete original resource baseline. The public projection exports this release class, counts and witness hashes, excluding global inventories, machine IDs, user UIDs, private paths and arbitrary logs. It does not query the current machine or infer failures from later separately authorized B services. All2090 recorded child cleanup rows were absent. The offline regrade's16 rehashed corruption controls and restored pristine result are retained as recorded contracts.

    Closed privacy transform¶

    Only the declared physical phases, table fields and semantic observations are exported. CURRENT37/OLD31 coverage is mandatory. Repeated metadata and rowsets are stored in content-addressed dictionaries and expanded before the independent comparators; no table is dropped or replaced by a success flag.

    The exact table-qualified fields in plan.opaqueFields use descriptors containing original primitive type, byte length and SHA256. They cover synthetic Transit ciphertext, secret references, credential/session material and key IDs. Equality relationships are preserved across tables and phases. Request/effect IDs and dedup/config fences remain synthetic causal data. After this declared transform, only unordered physical rowsets are canonically re-sorted; insertion ordinals, sequence state, timestamps and application-order fields retain their actual values. There is no provider/key-validity claim.

    The exporter verifies every indexed private input before selecting fields. Unknown nested fields, unbounded values, connection strings, private filesystem paths, raw stdout/stderr and process credentials are refused. The gate checks typed opaque fields, dictionary integrity/references, exact source bytes and explicit expected record content in addition to semantic predicates. Actual permission denials retain SQLSTATE42501 and null row count; a query that threw did not return a fabricated zero-row result.

    Run the archival gate¶

    With the pinned app objects present in the usual workspace object repository:

    node tools/queue/gates/m6-ops-recorded.js

    An existing alternate object repository can be selected without a checkout:

    NS_M6_OPS_RECORDED_REPO="$APP_OBJECT_REPOSITORY" \
  node tools/queue/gates/m6-ops-recorded.js

    The gate uses builtin Node modules and read-only git show/git rev-parse. It imports only the pinned independent oracle's pure comparison functions and replays all11 physical control predicates through the bound adapter. It never starts Docker, PostgreSQL, app jobs or provider sends, installs dependencies, fetches sources or writes a shipping tree.

    Authored corrupted-record controls deliberately recompute the projection digest so they reach the semantic predicates:

    node tools/queue/gates/m6-ops-recorded.js --control physical
node tools/queue/gates/m6-ops-recorded.js --control ordinal
node tools/queue/gates/m6-ops-recorded.js --control denial-null
node tools/queue/gates/m6-ops-recorded.js --control denial-code
node tools/queue/gates/m6-ops-recorded.js --control control-row
node tools/queue/gates/m6-ops-recorded.js --control secret-material
node tools/queue/gates/m6-ops-recorded.js --control missing-control

    Reproduce the projection¶

    The immutable private roots are explicit caller capabilities and are never serialized. The output files must be new:

    node tools/queue/gates/_m6-ops-recorded/build.cjs \
  --repo "$APP_OBJECT_REPOSITORY" \
  --native "$NATIVE_SQL_CAPSULE" \
  --reconciliation "$PRECISE_REGRADE_CAPSULE" \
  --out "$NEW_PROJECTION_FILE" \
  --plan-out "$NEW_PLAN_FILE"

    Two independent exports of the same indexed inputs produced byte-identical projection and plan files. The canonical projection digest is 3de6e8ccae2b6f9f9532316d1dca902d40a9c431d72e78d2916bbe8e1de22d28.

    R73, TEN-RESOLVE and the authored physical-corruption control now record the bounded queue wiring. Complete owner/identity/lifecycle, same-ID tenant restore, operating-envelope and production-admission contracts remain open.
