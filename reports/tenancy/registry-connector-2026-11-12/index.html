    Findings and controls¶

    Provisioning retries must refuse incomplete existing tenants¶

    Mechanism read-derived from the pre-repair implementation: registry tenant/host presence was sufficient for an existing result even if bootstrap state was missing. The repair checks structural completeness of the registry/key, control, settings and checkpoint families in the provisioning transaction. It refuses TENANT_PROVISION_INCOMPLETE/409 without recreating missing rows or replacing an existing root secret. Legitimate later changes and audit retention are permitted.

    Controlled reproduction: disabling only the new completeness decision made all four native PV_EXISTING_COMPLETE_* plants return existing rather than refuse: 0 pass,4 semantic failures. This is a repair ablation on the completed source, not a claim that a pristine original checkout was separately measured. Restored source passes in the 49 native check capture, and again in the final 58 native check capture.

    An initial activity plant hit a dependent audit foreign key before exercising the assertion; the fixture was corrected to remove that synthetic dependent audit first. The setup error was not counted as a semantic failure. The four-case ablation above is the corrected capture.

    Registry realtime must apply committed D15 settings¶

    Reproduced: valid stored mmol units, plugin selection and complete threshold settings reached API HTTP status while the registry realtime entry remained on mg/dl defaults. The pre-repair discriminator failed with 'mg/dl' !== 'mmol'. The repair uses a separate readonly D15 presentation reader for realtime entries and staged live admission; missing state refuses.

    The native discriminator reads actual PostgreSQL settings, uses actual HTTP API status serialization, and compares the actual realtime protocol's dataUpdate.status.settings serialization. It also checks another tenant's defaults, updates changing effective identity, and missing-state refusal. Projection rows and socket authority are synthetic; this is not a complete clinical-stream or live Socket.IO compatibility campaign. The isolated exact-leaf archive passes. A deliberate constant-settings mutation reproduces the units mismatch, and the restored final native bundle passes.

    Durable connector definitions and bounded refresh¶

    Definitions/history are D15 restorable tenant data, separate from operational tenant membership. Stable source IDs, generation CAS, idempotent retries and tombstones retain references to three distinct existing tenant secrets. The writer can inspect reference IDs and cannot read ciphertext. Metadata writes join the shared tenant maintenance lock, check active phase inside the transaction, and increment registry revision once. No clinical-write cost is added.

    Registry worker assignment refresh uses one aggregate revision read on unchanged polls. Changed revisions rebuild bounded per-tenant source pages and atomically publish a stable snapshot. Drivers retain bookmark/session when decrypted values are unchanged; each registry poll rereads references. Actual source/output requests recheck current generation and activity eligibility. Paused polling continues; suspended/deleted/disabled or configuration-refused work sends no new request.

    Native tests exercise CRUD/CAS, tenant RLS, foreign references, ciphertext refusal, actual admin HTTP, refresh/add/remove/alias, maintenance lock/phase refusal, history FORCE-RLS refusal and exact alias-definer body admission. A held-open source writer was classified by the actual restore backend census. Granting it clinical-clock write privilege made unknown-backend refusal; revoking the grant restored acceptance. That census uses controlled peer reporting for other actual fixture backends; it is not a full real-role restore acceptance.
