    Completed capability¶

    NS_M7_DIAGNOSTICS=1 selects process/role aggregate JSON log snapshots, default five seconds; NS_M7_DIAGNOSTICS_INTERVAL_MS accepts 1000..60000. Default OFF creates no worker, timer, clock reads or pool/client/async function wrappers. There is no new HTTP endpoint, schema, SQL, authority cache or credential policy.

    The normal PostgreSQL connection foundation, raw lifetime pool, raw membership pool and raw registry provisioning pool have constructor-only observation hooks. Public total/idle/waiting counts are read directly; checkedout is total minus idle. Observed outstanding client.query calls are separate from held clients. They include client-side query queueing and are not pg_stat_activity state. Query instances/custom submitters and config-owned callbacks are untouched and mark SQL coverage UNMEASURED. Direct pg.Client use, including the feed reader, is explicitly outside pool coverage and UNMEASURED.

    Fixed gauges distinguish shared worker lease handles, queued critical-section cells, active critical sections and outer body/response lifetimes. Admission, registration, API authorization, realtime RPC/private authorization and marker completion have separate fixed histograms. Body-response and completion timers are inclusive; admission is a registration subspan. Independent overlapping histograms have no request-level pairing: do not subtract percentiles or sum nested spans to infer exclusive cost or causal order.

    Resource bounds are 64 tracked pools, 13 buckets per fixed stage, and one transferred output buffer no larger than 8 KiB. Only selected source role names and process PID are labels. No tenant, token, request/socket ID, URL, SQL or error text is retained in snapshots. Overflow, unsupported forms and missing/zero observations are UNMEASURED. Closed pools leave the registry.

    The selected sink uses one unref'd worker, empty environment and no inherited application preloads. Busy/backpressured stdout drops snapshots instead of queuing JSON. Raw output failures/partial writes/EPIPE mark missing telemetry; the sink never wraps or closes application stdout. Shutdown does not await logging or promise a final flush. Enabled diagnostics add fixed per-process work/thread overhead; no zero-overhead or performance claim is made.

    Substantive failed observation¶

    The initial native run was two passes and one authored timing-oracle failure: a periodic one-second snapshot was incorrectly treated as proof that a body had been held at least 900 milliseconds. It need not be. The corrected instrument holds the same explicit 1100 milliseconds ON/OFF, excludes startup snapshots, and preserves the original SQL/body/restore/B/authority expectations. The final capture above passes; no runtime authority, clinical result or latency threshold was weakened. Failed local output remains in the evolving lane handoff.
