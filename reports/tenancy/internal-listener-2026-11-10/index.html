    The configuration as built (read-derived from the diff)¶

    This process's listener (serve.internal), lib/server/internal-api/listener-config.js:

    Key Environment override Default
    socket NS_SERVE_INTERNAL_SOCKET <runtime>/<roles>.sock. <runtime> is $XDG_RUNTIME_DIR/nightscout, else /run/nightscout. <roles> is the process's role list, sorted and joined with + (api.sock, api+realtime.sock).
    host, port NS_SERVE_INTERNAL_HOST, NS_SERVE_INTERNAL_PORT none. Both must be set explicitly; a partial pair is refused.
    shutdownTimeoutMs NS_SERVE_INTERNAL_SHUTDOWN_TIMEOUT_MS 5000 (0..60000). nightscout multitenant also requires it to be below its 10000 ms shutdown bound (exit 78).
    • socket and host/port are exclusive. Unknown keys are refused. When the default socket is used, its runtime directory is created with mode 0700 if missing. The existing transport check still requires an owned 0700 directory.
    • The resolver accepts a config object. nightscout multitenant passes {}, so today the settings come from the environment and the defaults only: no process config file carries a serve block (see open points).
    • Trust is unchanged: trust:'network', and the listener has no authentication. The public listeners (listeners.js) are untouched.

    Peer addresses: another role is reached at NS_<ROLE>_INTERNAL_URL (http://host:port) or NS_<ROLE>_INTERNAL_SOCKET. These are exclusive, and the default is <runtime>/<role>.sock. <ROLE> is upper case with _ for -, for example NS_TENANT_ADMIN_INTERNAL_URL. A role this process serves is always reached on the own listener; a wildcard bind is dialled on loopback. A peer address for an own role is refused when it names another socket, another kind of address or another port. A shared peer list may name the process by its service name (NS_API_INTERNAL_URL=http://api:7001 on the api process).

    Contracts are decided by role code, lib/server/serve/internal-listener.js:

    Role May serve
    api socket-authority (only with socketForwarding), lifecycle-participant
    realtime alarm-delivery, lifecycle-participant
    evaluator lifecycle-participant
    tenant-admin lifecycle-participant
    • The route table is fixed and the listener opens in serve.start, after the cohort and before any role boots. Each role binds its handlers after its boot; routes answer SOCKET_IPC_UNAVAILABLE until then. This keeps realtime's boot-time warm call to a co-resident api working.
    • Start-up refuses a binding for a contract the role does not own (INTERNAL_API_CONTRACT_UNOWNED) and any contract left unbound (INTERNAL_API_CONTRACT_UNBOUND).
    • A process with no contract opens no internal listener.
    • Each contract keeps its own byte and time bounds on the shared listener (new per-module bounds in transport.compose). The listener-wide bound is the widest of them.

    Removed with no compatibility shim (the preview is unreleased): endpoint-config.js; socketPathEnv/endpoint in socketForwarding, in the evaluator route and in cohort participant rows; apiSocketPathEnv/alarmSocketPathEnv/apiEndpoint/alarmEndpoint in the realtime config; operation-cohort.openControl(). Each old key is now refused by exact-key validation (tested).

    • Participant rows are {id, roles, namespaces, maxMessageBytes, timeoutMs}. The address comes from the roles, and all roles of one row must resolve to one address.
    • The Compose demo (deploy/multitenant/config.js, health.js) now uses /run/ns-ipc/<role>.sock for every role. The old alarm.sock and cohort-<role>.sock paths are gone.
    • Updated documents: docs/internal-service-api.md (new section "The internal listener"), docs/internal-service-topology.md, docs/tenant-operation-cohort.md, lib/server/realtime/README.md and evaluator-consumers-NATIVE-PLAN.md.

    Shutdown, transport.compose(..., {shutdownTimeoutMs}):

    1. close() stops accepting and destroys the connections that carry no dispatched call.
    2. A request that arrives while closing is refused with 503.
    3. Dispatched calls finish and send their responses, until the deadline. The check after the call now only requires the connection to be alive; before, it refused once closing had started.
    4. At the deadline, the remaining connections are destroyed. Their callers get SOCKET_IPC_UNAVAILABLE, which callers treat as uncertain with no retry, as before.
    5. close() still awaits the handler promises afterwards, as before.

    serve.start().stop() now closes the internal listener first, while the role contexts are alive, then runs the earlier sequence.
