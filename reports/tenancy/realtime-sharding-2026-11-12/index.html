    Controlled realtime sharding: focused core evidence, 2026-11-12¶

    Living document, last changed 2026-11-11 at 59c1fe4c5.

    The fixed-roster core capability is fixed on a local branch. Deployment binding and coherent joined full/browser/enabled-corpus acceptance remain separate gates; this report does not close MT-REALTIME-SHARDING or claim measured horizontal capacity.

    Source and instrument¶

    The final source includes the preceding helper history and coordinator history. All new product tests and native fixtures are committed in the complete leaf. The native runner starts only an owned disposable PostgreSQL image pinned by digest, with generated credentials passed through the environment; fixture-owned Vault instances are also disposable. The runner waits for actual external PostgreSQL TCP query readiness. No shared database or deployed operator tenant is used. Existing dependency installation was reused; no install, push, full campaign, browser campaign or capacity campaign was run in this lane.

    Controls and reproduced findings¶

    All five final-source controls exited red with their intended assertion, and restored byte-for-byte:

    Mutation Observed failure and interpretation
    Require globally equal route generation B alarm during unrelated A warm fails SHARD_NATIVE_HANDOFF synthetic B during unrelated target warm: REALTIME_HANDOFF_UNAVAILABLE. This is an actual availability defect, rather than a vacuous refusal test.
    Omit worker-coverage guard Missing declared RT participant produces Missing expected rejection. Completeness check is exercised.
    Ignore failed publication pin Pinned maintenance no longer rejects publication: Missing expected rejection. Actual database locking discrimination is exercised.
    Remove sharded envelope reservation Boundary configuration no longer rejects: Missing expected exception. Transport overhead bound is exercised.
    Remove legitimate registry-label response acceptance Actual unsharded API lifecycle status fails SOCKET_IPC_UNAVAILABLE; the former UUID-only contract prevented real registry health.

    The earlier warm-isolation failure is reproduced exploratory dirty-source evidence, not a pristine committed baseline: a new target projection was inserted in the active scheduler before acquisition completed, and holding that acquisition stalled B with SHARD_NATIVE_B_PROGRESS_DURING_WARM. The repair capture was green. The exact final native includes the same held-acquisition discriminator, plus failed-preparation refusal/recovery and concurrent pause before activation. Private staging keeps a cold/failed target outside the healthy scheduler; fresh activity, settings, registry membership and ownership are checked before activation.

    The narrow registry-ledger readiness repair was motivated by actual CLI refusal. The ledger-only discriminator removed only registry schema_migrations SELECT from an otherwise identical real role and reached the listener, then restored the grant. Product admission now allows exactly that reviewed ledger; unrelated registry-table SELECT still refuses in the final native. The first exploratory setup had an unrelated clinical-table grant outside the projection manifest; it was corrected in the fixture before the ledger-only comparison. No RLS, function owner, PUBLIC EXECUTE or unknown-backend census guard was relaxed.

    All-paused/suspended tenants stay deferred without clinical projection/checkpoint work. Real resumed tenants return to eligibility. A failed or slow target refuses handshakes and alarm effects; existing healthy tenants continue. The global publication/restore fence does not serialize every activity or deletion writer; fresh target checks are still required, and already in-flight work retains its bounded uncertainty.

    Integration boundary¶

    The coordinator owns ordinary merging of the core history, the matching shipping edge/platform binding, and one frozen comprehensive acceptance. Automatic failover, durable missed-alarm replay and horizontal capacity remain unmeasured/deferred. Local lane details remain in externals/work/HANDOFF-realtime-sharding-2026-11-12.md; they are not a public source of product state.
