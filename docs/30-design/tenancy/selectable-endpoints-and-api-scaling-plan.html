    Private API composition, deployment bindings and fixed-roster scaling¶

    Living document, last changed 2026-11-10 at 4917b2d4a.

    Living contributor-facing implementation plan, refreshed 2026-11-10 for the adopted internal listener shape and graceful shutdown. Current mechanisms are read-derived from joined application dc795bd1; carried measurements retain their original source/instrument in the linked evidence. Remaining criteria are UNMEASURED until their instruments run. Queue homes: MT-ENDPOINT-TRANSPORT, MT-API-FIXED-ROSTER; scaling and partitioning retain MT-SCALE-UNBOUND and MT-EVALUATOR-PARTITION. Read with the runtime topology. No production/default enablement follows from implementation or a diagram.

    Implemented foundation and remaining boundary¶

    The internal API implementation and joined dc795bd1 acceptance carry the shared transport, three service registries, executable request/response schemas, named clients, strict public/private separation and consuming-role configuration. UDS and actual loopback HTTP tests exist; the joined regression, browser, enabled-corpus and OIDC records have their own executed scope.

    Surface Current implementation Remaining adjustment or proof
    Private contracts Socket authority/mutations, alarm delivery and lifecycle participant operations have named clients and schemas. Compose explicit contract modules on a component-private listener without weakening ownership or lifetime checks.
    Binding UDS or explicit http: origin; optional independent bind address (per-contract references, replaced by serve.internal). Qualify a selected private network deployment, not merely a helper's loopback behavior. Direct https: is not implemented.
    Trust UDS permissions/UID/inode protections or explicit deployment-owned network reachability. Service/version headers identify the contract, not a caller identity. Exercise the selected deployment's reachability/access boundary. TLS/mesh/proxy integration, if selected, belongs to the deployment; no new bearer protocol is required.
    Listener allocation One service contract per listener. Public/management interfaces are separate. Adopted 2026-11-10: one private listener per role process, serve.internal, whose contract set the role's code decides; configuration cannot move or merge contracts. The public listener stays separate.
    Worker operations Evaluator has lifecycle control and in-process health(); realtime has a consumer-app health route. Define and integrate an operational health/readiness/metrics contract. A GET metrics endpoint and its response format do not already exist.
    API replicas API work is request scoped; fixed participant identity/drain mechanisms exist. Run two real equivalent APIs behind a service destination and prove all-instance maintenance, replacement and compatibility.
    Runtime cost Realtime obtains current authority during recipient fanout. Measure latency, request amplification, dependency failure and aggregate resource limits under MT-SCALE-UNBOUND.

    Private application calls and private lifecycle control are different purposes inside the same private API surface. They need not create separate transports, services or deployment processes. Data/authorization/owner REST modules may co-locate under existing audience and credential rules. REST v1/v2/v3 remain version adapters inside one logical request-serving component.

    Endpoint and compatibility contract¶

    Adopted configuration (decision, 2026-11-10, multitenant only). Each role process has one private listener, serve.internal, configured in the style of Ory Kratos/Hydra's serve.public/serve.admin: host/port or socket, each overridable from the environment (NS_SERVE_INTERNAL_HOST, NS_SERVE_INTERNAL_PORT, NS_SERVE_INTERNAL_SOCKET), with a default. The default is a unix socket under a runtime directory, because the internal listener trusts its network (trust:'network') and has no authentication of its own; network exposure requires an explicit host/port. Callers receive peer addresses (for example NS_API_INTERNAL_URL). The preview is unreleased, so the change carries no compatibility shim.

    Current code (dc795bd1, read-derived), which this replaces. Each contract has its own socketPathEnv or endpoint-descriptor reference with no default (lib/server/internal-api/endpoint-config.js:11-30; callers realtime/private-config.js, serve/operation-cohort-config.js, serve/evaluator-consumer-config.js), with service descriptions under contracts/ and usage in docs/internal-service-api.md. A Kubernetes Service DNS name can be the dial origin while a listener binds its own interface; a configured link-local/private address is supported, and loopback is not an architectural restriction. Public request content cannot choose private destinations. Credentials in URLs, unexpected paths/query/fragment components, unsupported schemes and implicit trust/fallback refuse, and the adopted shape keeps those refusals.

    Shutdown (decision). On SIGTERM the internal listener stops accepting connections, lets in-flight calls finish and send their responses up to a configurable deadline below the platform's termination grace, then force-closes what remains; callers still treat a force-closed call as uncertain. Reproduced on the listener-composition lane (Compose, d69b873a): close() dropped a held call at 176 ms while the server still drained its handler.

    Private operation payloads retain current tenant, credential, RLS, ACK and lifecycle semantics. Current service/version headers require a coordinated internal-peer upgrade; preserving the public client protocol does not establish mixed-version peer compatibility. Listener consolidation must specify any header, operation-path or schema migration explicitly; a URL must not be inferred from a malformed socket field.

    UDS-specific filesystem checks remain inside its adapter. HTTP reachability is supplied by the selected deployment policy. If established TLS termination or a service mesh is chosen, document its trust boundary and test the selected binding; do not infer process identity from a DNS name, port, header or successful probe. No new application cryptographic login, discovery service or orchestrator is needed to keep these contracts well defined.

    Remaining work and acceptance¶

    These owner roles name integration boundaries, not a new reservation ceremony. Confirm actual HEAD, current item openness and ownership before starting; stop and report a mismatch rather than substituting the nearest working mechanism. Keep each capability's helper, fixtures and meaningful controls in its lane.

    Optional gateway decision adapter¶

    Direct application-to-application calls retain the existing authentication and authorization semantics. Listener composition or using TCP instead of UDS does not inherently require changing those semantics. A native client can consume JSON; an edge integration can project selected decision fields into HTTP status and headers without making every private application call traverse a gateway.

    Read-derived prior art: inspected nightscout-roles-gateway 90840acee1ec641d881512e91f1728f7ed8f7817. Its GET/HEAD Warden chain uses the existing policy decision and then sets upstream routing headers (x-upstream-origin, x-forwarded-host); its token header adapter sets X-NSJWT. Nginx can consume response headers through auth_request_set without interpreting the JSON body. These code mechanisms are inspected, not a newly executed gateway or interoperability campaign.

    Nginx already handles public proxying and the Socket.IO upgrade. A selected auth_request/Oathkeeper-style integration would add a private decision contract: HTTP allow/deny/error semantics, original-request metadata, tenant resolution and which injected identity headers the application trusts. Reuse the existing authority component; do not duplicate its policy or use JSON {denied:true} as an HTTP allow. Client-supplied identity headers must not become trusted inputs.

    This adapter is a separately bounded optional deployment integration until its contract is selected. It is not an extra prerequisite for selectable UDS/HTTP transport. Connection admission does not replace subsequent message, subscription, recipient, exact mutation/ACK or current credential authorization. Deployment binding/trust work owns an adopted gateway profile; core owns its stable decision hook if one is selected. No new mandatory gateway or authentication product is selected by this plan.

    Evaluator workload and membership inspection¶

    The operational listener supports a read-only evaluator module whose payload is owned by MT-EVALUATOR-PARTITION. It reports configured mode/rule/version, member count, ordinal/incarnation and intended slice separately from observed membership/heartbeat agreement, freshness, conflicts and current eligibility. Expose aggregate assignment/progress/lag and handoff health, with bounded private drill-down where needed. Endpoint names and executable response schemas are still to be implemented; existing cohort status is not relabelled as ring health.

    Standalone mode reports all configured tenants without inventing a membership lease. Partitioned mode reports the actual slice and observed membership basis; ordinal configuration alone cannot make a stale/conflicting member healthy. Introspection remains callable while evaluation is blocked, does not schedule clinical work or acquire ownership, and does not clear lifecycle suspension.

    Acceptance uses actual evaluator processes and independently enumerated tenant assignments: member-count one covers the configured set; distinct members cover it without stable-state gaps/overlap; stale/mismatched count or duplicate ordinal is visible and blocks the affected computation. A mutant reporting only intended configuration as observed health must go red. Exercise membership-change overlap, recovery and duplicate durable/external effects under the existing M7 policy; the inspection API must not claim exactly-once execution from a hash mapping.

    The ownership inventory also covers notification attempts, future connector actors, realtime projections and maintenance claims. The shared operational module does not impose one common ring on these different work units or make them all stateless replicas.

    Service destinations, participants and workload owners¶

    Ordinary request-scoped calls may use an equivalently configured API service without pinning to the API that handled a prior request. A service must not retry an uncertain mutation automatically or route to an undeclared participant.

    Maintenance consumes a complete relevant roster, directly reaches each instance, checks actual datastore/backend and role/namespace identity, pins incarnation, drains actual operations and awaits every invalidation acknowledgement. Logical participant IDs can survive replacement; an old pin cannot accept a new process. A lost peer or uncertain commit/ack retains the affected tenant's suspension. A fresh authorized attempt follows existing cleanup/registration rules; this is not automatic restore resume or orphan clearance.

    Use supplied configuration/platform inventory. A routing table may exclude unready/terminating actors that still own operations, so it cannot automatically serve as the maintenance census. The native proof uses explicit endpoints; a Kubernetes/platform adapter is separate deployment work. No new membership or consensus service is required for the API capability.

    Evaluator and realtime replication remain separate semantics. MT-EVALUATOR-PARTITION carries the adopted optional member-count/ordinal and pool-membership contract; the default remains one workload owner. Realtime scale-out is scoped by the separate sharding/composition proposal, which owns placement, checkpoint and subset-aware maintenance changes and their acceptance. Neither is a reason to split REST version adapters into separate services or to block the already accepted foundation.

    Measurement and documentation boundaries¶

    MT-SCALE-UNBOUND owns synchronous authority fanout/dependency cost and aggregate API pools, database/Vault pressure, failure/recovery and healthy-tenant progress. Benchmarks retain synthetic workload, actual source/config, latency/queue/freshness and independent durable outcome oracles. Functional success is not a capacity or availability target. Metrics endpoint implementation does not itself supply that measurement, and a proposed cache must retain current-authority guarantees.

    Native runs use the adopted disposable harness and owned resource cleanup; there is no grant, lead reservation or freshness-attestation ceremony. Capture exact code/config/instrument identities, direct/service topology, complete participant coverage, real listener/transport and each red/restored symptom. Preserve failed predictions and distinguish actual clients/native processes from source doubles.
