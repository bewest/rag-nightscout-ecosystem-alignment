    Evaluator, realtime and API communication¶

    Living document, last changed 2026-11-17 at 5a19634fa.

    Contributor-facing living explanation, reconciled 2026-11-16 against selected cgm-remote-monitor 5e112547b31252ec428747c821d3cd1b3684ce2b and alignment records 5fdc4bf0685d35d2fac980bad1b28bd66525ccdb. Architecture is read-derived; reproduced acceptance retains its executed source/image in the current integration record. These mechanisms are fixed on local branches, not merged into dev or released. The bounded-input query census retains its separate inspected source below.

    This guide owns component responsibilities, accepted versus completed state, raw storage delivery and recovery. Decisions remain in tenancy decisions, the durable event contract, owner authority and release decisions. The queue owns claimed work state; release contents own qualification and publication.

    Stream-fed clinical materializer¶

    The evaluator consumes committed clinical inserts, updates and deletes into a bounded tenant working set. Routine warm changes apply accepted rows; they do not reacquire a full clinical source snapshot. Settings, policy and lifecycle changes join the same processing contract. Preserve existing identity, ordering, units, clinical algorithms, extension fields and client contracts. Source JSONB retains original clinical fields; generated typed SQL columns and typed metadata already support identity, ordering and stream admission.

    Transport acknowledgement follows cheap validation and recoverably accepted input. Evaluation, viewer delivery and provider I/O run separately. Transport position and clinically completed input/settings versions are distinct. A transaction cohort becomes visible coherently; clinical dates do not define coverage. Durable input or consistent snapshot/replay recovery must reconstruct all accepted work after process loss. Snapshots serve bootstrap, gaps, cache loss and missing historical needs; warm event handling applies streamed rows.

    One bounded scheduler owns startup, unfinished versions, actual clinical due work and recovery, with fair tenant selection and serial execution per tenant. Completion atomically persists covered versions, result/frame/revision and next due under current authority, ownership and restore fences before RAM advances. Newer input stays pending. Realtime consumes completed output, applies current viewer authority/demand, and keeps one retry responsibility per owed delivery. Durable receipts recover lost wakes; external exactly-once delivery is not claimed. Healthy idle has no hot full-roster polling or per-event catalogue screening.

    Boundary Implemented branch behavior and qualification boundary
    Clinical CDC and durable acceptance Six clinical routes retain typed identity, extension fields, physical storage size and insertion order. Raw rows commit to the existing input checkpoint before transport ACK. In the inspected implementation, an XID (transaction identifier) cohort seals with its matching clock-table event, atomically with the typed observed-work receipt. That current dependency is evaluated under the transaction-coverage direction. Same-LSN COPY rows remain distinct.
    Working set and recovery Warm evaluation reads the accepted clinical window, without full clinical source reacquisition. Consistent bootstrap uses the engine's historical exceptions and settings; whole-history storage statistics stay authoritative outside the clinical cache. A known row/byte overflow durably marks a non-ready gap, evicts the input cache and preserves the sealed clinical floor and completed output; bounded successful bootstrap is required before evaluation resumes. Malformed data is refused.
    Scheduling and completion One bounded scheduler owns startup, pending, due and recovery. A held tenant leaves free slots and later recovery pages available to neighbors. Retry backoff belongs to the failed tenant. Concurrent earliest-due reads coalesce, with a fresh lookup after changed work and safe ownership release before settlement. TIME acquires newly observed input before completion; input arriving during evaluation remains owed. Result/frame/revision, covered versions and next due commit under existing ownership/current-authority/restore fences before RAM completion.
    Realtime The completed-output path distinguishes upstream pending, unwatched/deferred and ineligible work from actual failed delivery. Durable receipts own owed-delivery retries. Realtime does not build a raw clinical projection.
    Optional path The separate selected-intake materializer remains unqualified and is explicitly refused before effects by the public evaluator configuration. It is not the default path or a prerequisite.
    Qualification Focused default native tests include coherent corrections/deletes, process recovery, due work without a write, held-neighbor progress and unchanged warm snapshot/statistics query counts. Source-scoped controls are in the existing discriminator harness. The current integration record owns selected-source qualification; operating measurements retain separate attribution.

    Single-evaluator efficiency plan¶

    Execution priority requested by the maintainer, 2026-11-16: improve one evaluator before expanding evaluator replication, while preserving a path to the 100,000-plus-tenant fleet. This is a plan, not a capacity qualification. Mechanism assessments are read-derived from qualified core c31c6e0b69a2a2f2a5320b9e4d32195f1b3e1878 and receipt follow-on c1173eab7c4fea1270eb585aff5961142849d048, with deployment 92227d9d4853ed75c5f1ea10c0ba00f03bd2dac5. An unchanged frame can still cover new input; a due cycle can be required without a source write. Fleet population is not a claim that one process or database serves that population.

    Keep, replace and regroup¶

    Responsibility or mechanism Disposition and boundary
    Shared committed-change detection Keep pgstream as the selected transport. Discover work once rather than restore per-worker/per-tenant polling. One receiver and one replication slot do not distribute clinical execution by themselves.
    Durable acceptance, completed coverage and pending work Keep the distinct outcomes. Acknowledge only recoverable input; completion covers only the input/configuration actually evaluated. Newer input remains pending. Reuse existing durable stores rather than add a broker or general event log.
    Clinically sufficient input and source truth Keep explicit row/byte bounds and consistent recovery. Clinical windows, historical exceptions, typed identity, ordering and extension fields remain required. Source history is authoritative; a clinical cache is replaceable. Incremental windows versus coalesced snapshot rebuilds are a measured design comparison, not a reason to narrow clinical inputs.
    Clinical scheduling Regroup under the existing bounded scheduler: startup, accepted pending work, recovery and actual due deadlines. Keep serial work within a tenant, progress for healthy neighbors, tenant-local retry backoff and bounded concurrency. Do not add an independent retry owner for the same obligation.
    Clinical result and browser frame Keep one clinical interpretation. Evaluator produces both using shared engine primitives. Realtime consumes completed output and does not reacquire clinical history or run a second clinical projection. Remove redundant copies only with equivalent clinical/client output and recovery controls.
    Transaction completeness and internal progress Evaluate replacing clock-event sealing using the exact connector contract or a coherent invalidation/snapshot alternative. See transaction coverage. Native WAL semantics alone do not qualify the webhook boundary. Public history and insertion ordering retain their separate contracts.
    Receipt SQL, JSONB envelopes and encoding Optimize physical work, preserve semantics. A mandatory row rewrite, SQL shape, RAM generation or acquisition/TIME label is not a product obligation. Retire displaced executable code and mechanism-only assertions together, with semantic controls. Acknowledged input must never exist only in RAM.
    Authority, activity, ownership, schema and restore checks Keep their guarantees; consolidate equivalent reads. Batch addressed trusted metadata work and keep current effect/completion fences. Do not replace current authorization with a cached prior allow decision, or run expensive catalogue admission for every event without a demonstrated requirement.
    Completed frames, raw mutations and alarms Keep different delivery contracts. Current display frames may supersede older frames; raw subscriptions preserve required operation order or explicitly lose continuity; alarms retain stable intents, suppression, attempts and retry deadlines. Shared helpers must not erase these distinctions.
    Optional membership, placement and process topology Keep outside the unpartitioned hot path. A standalone evaluator owns its configured eligible tenants without fabricated membership leases. Existing optional partitioning remains available. Additional workers, threads, services and pool connections need a measured reason.

    The selected design already separates input acceptance, clinical completion and external effects. Co-locating code may remove a network hop; it does not remove these durable boundaries. Conversely, different logical responsibilities do not require different processes. Bound intake, clinical and delivery work so a slow provider, viewer burst or expensive tenant cannot exhaust the whole worker.

    Measurements and implementation order¶

    Use the existing runner and bounded diagnostics. Freeze source/deployment/image, instrument, workload, CPU/memory limits and database history for each comparison. Retain originals outside Git and report shared-host interference. Start with the smallest discriminator that can select a design; a broad capacity sweep is not the prerequisite for isolated synthetic profiling. An independently owned branch experiment may start before final source acceptance; label its unqualified source and scope. Source-owner release means permission to use the named checkpoint, not a requirement to wait for every acceptance tier before collecting evidence.

    3 — efficiency continuation Profile CPU and allocation/GC across cache application, decoding/encoding/freezing, view materialization, engine execution, digest and frame creation.     5 — operating owner after source release Run a matched sustained operating comparison on the coherent selected candidate, including startup, steady traffic, quiet due work, burst, restart and backlog drain. If evidence refutes a prescribed fix, retain the measured result and choose the simpler supported mechanism. Missing optional metrics narrow that claim rather than invalidate independent observations. Join planned repairs before one coherent applicable final campaign and final prcheck; leaf changes do not each trigger a new comprehensive campaign.

    Preserve the horizontal execution seam¶

    Keep intake ownership separate from permission to execute clinical work. The unpartitioned evaluator owns all its eligible tenants; future selected workers own subsets through the existing assignment contract. Pending input, completed coverage, output and due obligations survive process replacement. Completion and effects reject stale authority/ownership/restore state; assignment alone does not prove those checks or duplicate-effect safety.

    A future worker must select only its assigned pending/due work, without replaying all tenants' input or performing full-roster screening. Qualify membership change, cache transfer/rebuild, old-worker exclusion or the admitted overlap policy, duplicate alarm prevention and recovery before claiming horizontal execution. Equal tenant counts need not mean equal CPU or memory. A single intake owner can feed several execution workers only with a qualified work-distribution boundary; a load-balanced receiver address is not that boundary. Keep this seam explicit now; defer new fleet/placement machinery until single-worker measurements justify it. The topology ownership inventory owns the other roles' scaling semantics.

    Internal trust and state ownership¶

    Evaluator and realtime are trusted internal roles that work across tenants. Internal CDC payloads may contain clinical, configuration and completed-output rows. A blanket non-clinical-only feed is not an isolation requirement. Reuse existing rows and versions; add a marker only where it makes coalescing or recovery simpler. Do not add tables or rereads solely to hide data from these trusted workers. Current tenant identity, authority, ownership and restore state still govern computation, persistence and externally visible effects. Trusted metadata work may batch across tenants without a per-event catalogue screen or public request-admission path.

    One receiver in the evaluator role durably coalesces observed versions before returning HTTP success. Evaluation drains observed-versus-completed differences separately, so clinical computation does not hold the serial CDC delivery open. The existing evaluator checkpoint consumer retains observed and completed versions, completed result/frame, content revision, next due instant and ownership/restore generation. Acquisition and clinical completion remain separate.

    The platform restart decision places pgstream in an independently managed service. It sends webhooks to the evaluator's private receiver. The platform owns the pinned process and its restart policy; the evaluator owns durable receipt, clinical completion and application readiness. A stream outage withdraws readiness and recovery reconciles current state. Restarting pgstream does not itself require evaluator exit. Existing internal API and deployment trust conventions apply.

    Each replication slot has one active stream consumer. Delivery must reach the current receiver owner, or an ingress implementation that provides equivalent durable admission. The current selected binding targets its sole intake owner; ordinary load balancing across evaluator replicas is not qualified by the private Service address. Receiver availability and clinical readiness are separate so service discovery does not require clinical readiness before delivery can start.

    The historical bounded platform witness measures a Docker-managed stream replacement with the same evaluator and exact durable catch-up. It does not qualify the new application image, Kubernetes, general failover or a capacity limit.

    Completion commits the result, processed versions and next due together under a current ownership/restore fence. A newer version remains pending when an older cycle finishes. Reuse current transactional write clocks, settings/activity versions, notification producer identities and recovery contracts. Clinical dates and CDC arrival order never stand in for commit versions.

Per-row bytes of cached rows alone cannot answer this statistic.

    The query compiler and existing engine own type handling, units and ordering. Entries use numeric date; the other range queries compare created_at with an ISO string. Replacing that membership test with a permissive date parser can change answers for legacy or malformed values. Preserve the existing filter's type and array semantics. Those queries have no upper time bound unless the loader is explicitly asked for a framed historical read (lib/data/dataloader.js:188–192,367–368,423–424). Future records therefore stay eligible input. They become clinical work when their time arrives (lib/data/evaluator-due.js:62–65). The cache does not discard them as “too new.”

    Typed identity is (domain, id_kind, _id); a string and an ObjectId with the same hex text remain distinct (lib/storage/postgres-identity.js:13–38). Preserve each row's insertion ordinal and the existing total-order tie-break. Keep original clinical values in durable input; unit and duration normalization remains in ddata, including temporary-target conversion (lib/data/ddata.js:37–79,469–505). A record with isValid: false stays out of clinical answers, while source history and byte accounting still include it (lib/server/soft-deleted.js:3–24). A late correction is classified by its new contents; commit coverage is classified by the stream's versions and cohort, never by the record's clinical date.

    One existing scheduler owns expiry, clinical due work and recovery. Expiry removes only derived rows and schedules the next boundary even without an input write. Shrinking a window can prune its derived state. Expansion, backward clock movement or a ranked winner lost from a reduced candidate set requires a named historical recovery path before completion. A consistent tenant-bound snapshot includes the required source ranges and its input floor; replay overlap skips cohorts already covered by that floor and applies later committed cohorts whole. Restart may reuse a compatible durable working set. An incompatible policy, schema or restore generation must recover rather than reinterpret old coverage. Routine warm changes apply accepted row data; a legitimate missing-history fetch has a separate recovery reason and is not an every-change full-source reconcile.

    Window membership is not a hard memory bound. Declared row and byte limits still refuse a clinically required set that exceeds them; the implementation must retain pending work and the last completed output without certifying the refused version. Fleet admission must also account for retained decoded/prepared input, plugin and date caches, staged cohorts, result/frame copies and in-flight evaluations. Cold cache eviction preserves durable pending versions, deadlines, notification state and completed output. It must not turn tenant admission into roster scans or repeated failed bootstrap attempts. Viewer presence does not control clinical admission or deadlines.

    Derived expiry never deletes source rows. Source retention is separately optional: API v3 autoprune runs only when configured, and profile pruning is an explicit API DELETE operation (lib/api3/generic/collection.js:33,139–180; lib/api/profile/index.js:232–240). Neither guarantees the population fits a clinical cache. REST history/export and logical restore retain their existing source contracts. Restore invalidates derived membership under its existing suspension, authority and generation fences. Whole-history accounting must survive that invalidation independently; identity-only deletes and unchanged-TOAST updates cannot derive an evicted row's former byte size from its absent cached document.

    Clinical evaluation remains current-state computation. This cache does not create a guarantee to evaluate every superseded intermediate row version. Transaction cohorts must remain coherent, and durable notification requests already produced retain their identities, suppression and retries. Any consumer that requires an intermediate transition needs retained event/effect semantics before coalescing; window expiry or latest-state replacement cannot silently satisfy that obligation. Realtime continues to consume the completed result and current viewer authority, not a second raw projection. Qualification must compare actual engine answers and frame fields, distinguish required historical recovery from warm rediscovery, and prove that expiry neither deletes source data nor completes unseen input.

    Raw storage delivery is independent of clinical membership¶

    The focused precursor implementation is application branch codex/bounded-storage-20261116, commit 3e085e056330d2f0ddf29c4000e526a968462620. It includes the integrator's committed 1dc7a74576b5d77f99cc4a42d900e1692d94a393 scheduler and populated-backfill repairs. It is fixed on that branch and joined into the selected streamlined candidate. Its focused evidence retains its original source; the current integration record owns joined acceptance.

    The input checkpoint carries two JSONB envelopes: the clinically sufficient working set first, a bounded source-mutation tail second. An accepted source row and its existing completed-checkpoint delivery revision commit in the same transaction before transport acknowledgement. The raw tail shares the existing input-row write; the completed frame is not rewritten for each raw event. Clinical bootstrap, expiry and GAP replacement preserve the second envelope. Lifecycle/schema invalidation resets its continuity under the existing fences. No new tenant table, broker, consumer retry loop or source-history projection is introduced. Whole-history statistics still use postgres-tenant-stats.

    The existing realtime receipt drain refreshes addressed controls once, consumes completed frames without clinical row transfer, and independently delivers raw mutations to storage subscribers. Each raw delivery failure remains local to its tenant. Current worker, owner, restore-generation, activity and viewer authority still fence publication. No viewers means no raw-tail fetch or retained offline client obligation. Notifications keep their independent clinical deadlines.

    A storage subscription records the current mutation sequence and then receives later normalized operations in source order. Its existing packet supplies no initial population, offline cursor or reset event; reconnect begins another live subscription. Exact retained retries are idempotent within the live cursor; external exactly-once delivery is not promised. A temporarily uncertain authority holds its cursor for recheck. If that cursor falls behind the bounded tail, the server disconnects it with REALTIME_STORAGE_CONTINUITY_LOST; it does not silently coalesce required mutations. An older concurrent tail read cannot move a cursor backwards. Clinical expiry emits no source event. Food/activity and out-of-window corrections/deletes remain raw events even when absent from clinical input.

    Append-only migration 0100_<domain>_storage_identity sets source tables to REPLICA IDENTITY FULL. Actual old documents preserve public delete identifiers that differ from typed _id, including TOAST values. Metadata-only updates with unchanged documents emit no client mutation. Catalogue checks accept only this exact typed operation; readiness refuses the old identity mode. Existing RLS, grants, logical export/restore/delete inventory and single-tenant socket wiring remain the authority for those responsibilities.

    The focused qualification record contains the reproduced engine/history/expiry, native WAL/COPY/replay/RLS, current-authority, fleet-cache and mutation-control results, exact sources and retained evidence. The integration record now owns selected-source actual-role client and full/browser/enabled-native qualification. Operating profiles and capacity retain separate source, evidence and claims.

    The selected stream path keeps warm replay read-only, including time-only expiry. It reads only the clinical component, without transferring the raw delivery tail. The existing receipt seal advances the window using the last completed clinical engine instant and prunes it while owning the input transaction. Idle state cannot grow. Evaluation can remove more expired rows locally; distinct remaining subsets carry distinct progress identities. Clock rewind or settings expansion uses consistent recovery. This avoids a checkpoint write and full policy comparison on each warm cycle.

    Completed stream output keeps the clinical result and stock-client frame without a second copy of raw clinical rows. The input checkpoint owns those rows; the independent mutation tail owns raw delivery. Nonstream snapshot output preserves its established row contract. Realtime reads completed output and the raw tail under current tenant authority; it does not reconstruct clinical projections.

    Raw publication opens its tenant operation before it validates a captured tail. It then checks current authority and every send within that operation. A closed read operation cannot supply an active publication scope; retries retain the owed delivery instead of bypassing restore checks.

    Bounded state transitions replace changed envelopes and arrays while sharing read-only retained values. Raw-tail eviction counts exact UTF8 bytes once and subtracts removed elements. Persisted size estimates do not override an exact fresh bound; overflow, cohort and prior-state mutation controls remain.

    Qualification follows durable outcomes. Cache eviction may advance a disposable component generation, and due work may need an acquisition after cache loss. Neither a stable RAM generation nor a particular acquisition/TIME counter split is an enduring clinical requirement. Preserve process/restart provenance, monotone completed coverage, pending work, due obligations, current authority and restore fences. A counter-only observation cannot establish those durable properties or justify relabeling an earlier failed capture.

    FULL replica identity is retained for the selected candidate. It supplies the old public identifier and unchanged TOAST document required for truthful deletes and corrections without another history projection. Its synthetic WAL cost is material, so this is an explicit correctness/storage trade-off. It is not an established throughput cause or an assertion that every future storage design must use FULL. A replacement must preserve old identity semantics and recoverable acceptance before acknowledgement.

    Full old identity adds WAL bytes for unchanged documents; the qualification record measures that trade-off in a synthetic fixture. It does not establish serving latency, capacity or the cause of the earlier delay. Whole-history statistic scans and total fleet heap/RSS remain unmeasured here. The bounded clinical set may still exceed its declared limits when actual required input is too large; that stays pending/refused rather than completed.

    Notification intents, retries and alarm handoff¶

    The evaluator notification component owns durable producer, suppression, request and attempt state. Realtime owns authorized connected-browser fanout. A stable request identity survives an uncertain response or restart. Attempt state commits before external I/O; retries recheck current eligibility, suppression, authority and restore state. A handoff receipt does not prove browser display, human acknowledgement or provider/device delivery. External exactly-once delivery is not claimed.

    Content-identical clinical cycles keep their output revision under the content-revision decision. Durable completed coverage may advance without changing the frame. An active, unacknowledged, unsnoozed alarm repeats on its own heartbeat clock. Paused or suspended tenants neither compute nor deliver alarms; resuming requires current eligible output under the activity policy.

    Browser authorization and mutations¶

    Main, storage and alarm namespaces retain their existing credential, subscription and callback contracts. Realtime forwards the original client authorization and mutation envelope to the API's private contract. API independently resolves the tenant, checks the current credential and permission, and invokes the canonical socket write or suppression handler. Transport identity does not replace client authority. Ambiguous failures produce no synthetic success or automatic mutation retry. REST v1/v2/v3 remain adapters of the same request-serving component.

    A registered tenant operation lasts through actual response or publication completion. Each send rechecks current authority inside that operation. Maintenance uses the complete participant roster and actual backend/incarnation pins to drain work and invalidate tenant state. A service address is not that roster. The runtime topology owns private listener composition and owner authority owns credential/audience boundaries.

    Recovery, compatibility and qualification¶

    Process-local caches may be evicted or rebuilt. Durable accepted/completed positions, pending input, actual due work and current ownership/restore generation determine recovery. Due work must complete whether the runtime labels its cycle acquisition or TIME. A later next-due time can be legitimate; completion does not require all future deadlines to disappear. Unclassified rejected-attempt counters alone cannot establish a clinical failure or its cause. Actual wrong output, missing coverage, authority loss and durable rewinds remain failures.

    Lost-slot recovery stops serving, reconstructs consistent accepted/completed state and verifies current due/restore state before explicit reopening. A revision upgrade and rollback require the admitted source/deployment pair and compatible WAL/input contracts. The existing integration record owns the reproduced ordinary recovery, populated upgrade, cold rollback, selected client and final full/browser/enabled-native results, including pending cases. It preserves the different executed image/helper attributions. The production path explains remaining deployment admission; the operating report owns workload measurements. Functional qualification does not establish capacity, HA, a live provider or all clinical production behavior.

    Single-tenant behavior, stock client code and wire formats retain their existing contracts. Stream output omits duplicated clinical rows; the nonstream snapshot contract and independent raw storage events retain their own fields.
