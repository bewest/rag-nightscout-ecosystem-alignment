## Lab smoke: Nightscout-to-Nightscout

Everything runs on 127.0.0.1 with host Node (`n exec 22.23.2 node
lib/server/server.js`). No image was built.

- **Source**: `1f9a9d10` in a detached worktree (`externals/work/crm-dev-36b-src`),
  port 3561, `AUTH_DEFAULT_ROLES=denied`, database `rcc36b_labsrc_test` on `rcc-mongo7`.
  It was seeded and then fed by `tools/lab/connector-soak/writer.js` (synthetic only:
  60 h seed of 730 entries, 280 treatments, 240 devicestatus, 1 profile, then live
  writes every 5 min).
- **Proxy**: a copy of the lab's `proxy.js` that also logs response byte counts
  (port 3562). It logs no headers, query strings or bodies.
- **Sink**: the rc worktree, port 3563, `AUTH_DEFAULT_ROLES=denied`,
  `CONNECT_SOURCE=nightscout`, `CONNECT_DEBUG=true`, endpoint = proxy, source API
  secret (the lab's K2 mode). Database `rcc36b_labsink_test`, dropped before each pass.
- Secrets were generated with `openssl rand` into mode-600 files and never printed.
- In each pass, after poll 2, the source's one profile was edited through `PUT
  /api/v1/profile`, changing only its `dia` value and leaving `created_at` alone.

Pass 2 is the result: rc `d087588f`, connector `0.1.0-dev.3` from npm, 5 polls,
21:48:32Z to 22:05:42Z. Pass 1 used the rc at `ec70aab0` with the `de3cee1` tarball,
4 polls, 21:22:22Z to 21:35:28Z. It started with a fresh subject; pass 2 reused the
`nightscout-connect-reader` subject pass 1 created on the source.

**Per collection, at the last poll.** "In window" means source records timed from
(first poll − 48 h) to the last poll. Records are matched by the writer's `soakId`.
The profile's `startDate` is 60 h back, before the window. It is the profile in
effect when the window starts, so the connector reads it by design.

| collection | source total | source in window | sink | twins | missing in window | on sink, not on source |
|---|---|---|---|---|---|---|
| entries | 750 | 587 | 587 | 0 | 0 | 0 |
| treatments | 288 | 225 | 225 | 0 | 0 | 0 |
| devicestatus | 246 | 192 | 192 | 0 | 0 | 0 |
| profile | 1 | 0 (in effect at window start) | 1 | 0 | 0 | 0 |

Pass 1 had the same shape: 586/586, 224/224, 192/192, 1/1, with 0 twins and 0 missing.

**Poll spacing.** Pass 2 started polls at 21:48:32, 21:50:30, 21:55:40, 22:00:25 and 22:05:42,
spaced 118, 310, 286 and 316 s. Pass 1 spacing was 200, 291 and 296 s. The short first
interval is the connector aligning its schedule to the source's data. There was one
request per collection per poll, with no retries. All 28 proxied requests in pass 2 answered 200.

**Profile bytes per poll** (response bytes at the proxy; profile responses were not
compressed):

| poll | requests | bytes |
|---|---|---|
| 1 | `profiles.json` window query (2) + `profiles.json` in-effect-at-start query (671) | 673 |
| 2 to 5 | `profiles.json` created since bookmark (2) + `profile.json?count=1` newest (671) | 673 each |

The first poll's entries, treatments and devicestatus bodies were 10688, 2863 and
5661 bytes, brotli-compressed. Later polls were 2 to 278 bytes each.

**Update on change.** In both passes, the poll after the source edit copied the new
`dia` to the sink's profile under the same `_id`. The sink kept one profile document,
with no twin. The bookmark query returned nothing, as expected, since `created_at` did
not change; the copy came through the newest-profile read (BFQ-97's first decision).

**Secrets in logs.** The source and sink logs, the proxy log and the writer log were
scanned for each API secret (raw and SHA-1) and for the reader subject's access token.
**0 matches in every file, in both passes.** The only line in the sink log that mentions
the secret is the boot message `API_SECRET has 248 bits of entropy`.

**Log contents.** The sink log holds the `TRUST_PROXY`-unset security notice (auth-hardening's
boot message) and `simplealarms` Warning LOW notifications raised by the synthetic readings.
There are no errors.

**A setup defect of our own, not counted.** The first sink start sourced an env file
in which the `ENABLE` value was not quoted, so `connect` was not enabled and the sink
logged "Skipping connector without a source". The value was quoted, the source and sink
were restarted, and the sink database was dropped before pass 1.
