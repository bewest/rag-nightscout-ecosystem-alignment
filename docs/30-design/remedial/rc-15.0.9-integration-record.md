and tested. Current run: 2026-09-25, run 016, the release candidate: full local merge `rc/15.0.9-full`

### Failures

None of these fail on the `dev` baseline.

**Four `language` tests fail in all six cells from step 5 (#8730) on.**

| test | expected | got |
|---|---|---|
| "translate to Taiwan Traditional Chinese" | `碳水化合物` | `碳水` |
| "preserves Traditional Chinese volume units and uploader battery labels" | `毫升` (millilitres) | `克` (grams) |
| "preserves Swedish report filters and record count placeholders" | `Dagar med mat` | `Days with food` |
| "substitutes the Russian status update time without losing values" | `5.5, стабильно, последнее обновление 12:30.` | `5.5 и стабильно начиная с 12:30.` |

- #8730 is a Crowdin sync. It overwrites strings that `dev` fixed and pinned with these tests.
- In zh_TW, the volume unit `"ml"` becomes `克` (grams), and the "Pump Battery Low Alarm" label is
  dropped.
- Swedish "Days with food" goes back to English, and the Russian status string reverts.
- A wrong unit label in the UI can be misread, so this is a user-facing regression, not only a test
  change.

**One `tests/loopnotifications.test.js` "after all" hook times out on Node 20 and 22.**

- The test is "API tests for iOS Loop push notifications" / "Sends valid JWT Bearer token in
  Authorization header", and the error is `Timeout of 10000ms exceeded`.
- It fails on Node 20 and 22 in every run and passes on Node 24. It first appears at step 4.
- The test file comes from #8419 and does not exist on `dev`.
- #8419's head `b1c23e74` on its own reproduces it: 2 of 2 runs fail on Node 22, and 2 of 2 pass on
  Node 24. So the merge does not cause it.
- The hook ends with `fakeAPNServer.close(done)` on an http2 server. An APNs client session left
  open is the likely cause. It is not verified.

### Live server checks

These ran against a server booted from the real `lib/server/app.js` on `1b1977e0` (run e). That tree
is `dev` `74fc6619` plus every unit except #8758, and it carries #8754's final trust-proxy code.
Each check sent a request without forwarding headers, then one with a two-entry `X-Forwarded-For`
chain and `X-Forwarded-Proto: https`, both from the loopback peer.

| `TRUST_PROXY` | boots | client address for a chained request (`req.ip` = throttle key) | `req.secure` |
|---|---|---|---|
| unset | yes, with the unset security warning | left-most forwarded entry, as 15.0.8 resolves it | true |
| `false` | yes | the socket peer | false |
| `127.0.0.1,::1` | yes | the entry the trusted peer added | true |
| `1` | yes | the entry added one hop away | true |
| `true` | yes, with the every-hop security warning | left-most forwarded entry | true |
| `0` | no: startup error naming the accepted forms | | |

With no forwarding headers, every setting that booted gave the peer and `secure: false`.

with records, and a malformed count answers 400. A DELETE with a zero or invalid count answers 400

## Method

Every run follows these rules. A run that departs from one says so in its own section.

- **Candidate by SHA.** The candidate is built from `dev` by SHA, one `git merge --no-ff` per unit,
  and never pushed. Each unit's head is checked against its PR head before merging and again at the
  end of the run.
- **One mongod per cell.** Each cell gets a fresh `mongo:<ver>` container with
  `--ulimit nofile=64000:64000` (the #8758 suite peaks near 1130 open files). The server version is
  read from the container before the cell runs. The database is dropped before every run.
- **Rebuild the bundle after every merge.** The client tests run against the production webpack
  bundle, so a stale bundle reports an already-fixed defect.
- **A cell that prints no mocha totals counts as a failure.**
- **Additivity by title.** At each step, the sorted list of passing test titles is compared with the
  previous step's, leaving out lines that carry a generated ObjectId. A step may add only its own
  unit's titles.
- **Break-its count only when the failures show the defect.** A break reverts or edits one unit's
  fix, runs that unit's tests, and restores. `git status` must be clean afterwards, and the tests must
  pass again.
- **Harness red control.** The same runner is pointed at a tree or database set up to fail, to show
  that a green result depends on what it claims to test.
