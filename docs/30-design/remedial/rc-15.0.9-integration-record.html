    Method¶

    Every run follows these rules. A run that departs from one says so in its own section.

    • Candidate by SHA. The candidate is built from dev by SHA, one git merge --no-ff per unit, and never pushed. Each unit's head is checked against its PR head before merging and again at the end of the run.
    • One mongod per cell. Each cell gets a fresh mongo:<ver> container with --ulimit nofile=64000:64000 (the #8758 suite peaks near 1130 open files). The server version is read from the container before the cell runs. The database is dropped before every run.
    • Rebuild the bundle after every merge. The client tests run against the production webpack bundle, so a stale bundle reports an already-fixed defect.
    • A cell that prints no mocha totals counts as a failure.
    • Additivity by title. At each step, the sorted list of passing test titles is compared with the previous step's, leaving out lines that carry a generated ObjectId. A step may add only its own unit's titles.
    • Break-its count only when the failures show the defect. A break reverts or edits one unit's fix, runs that unit's tests, and restores. git status must be clean afterwards, and the tests must pass again.
    • Harness red control. The same runner is pointed at a tree or database set up to fail, to show that a green result depends on what it claims to test.
