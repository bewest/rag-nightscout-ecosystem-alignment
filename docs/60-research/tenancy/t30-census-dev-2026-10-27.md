# The tenant configuration census, re-measured on dev (2026-10-27)

*Contributor-facing. Snapshot, 2026-10-27: cgm-remote-monitor `official/dev` `7abe1cf6`, against the
census taken on the seam branch `81a1f6ce` (queue `T30-RESEARCH`). Measured with this repository's
census gate; the per-name lists are read from it. Nothing here is decided: the contested settings in
§3 are for the maintainer.*

The tenant-owner configuration surface
([§B](../../30-design/tenancy/tenant-owner-config-surface-2026-09-15.md)) classifies every setting a
Nightscout site reads as **T** (the tenant owner may set it), **TS** (a tenant secret), **D** (a
deployment value the hoster pins), **B** (bootstrap, single-tenant only) or **X** (not applicable).
It was counted at 277 names on the seam branch. The maintainer asked for it to be re-measured on dev
before the decisions are walked through.

## 1. Count

```sh
node tools/queue/gates/t30-census-differential.js --ref 81a1f6ce      # 11 checked, 0 failing; code 277
node tools/queue/gates/t30-census-differential.js --ref official/dev  # 11 checked, 4 failing; code 264
```

**264 on dev** = 277 − 21 + 8, reproduced by session -ee. A `git grep` of every `readENV`-style
literal in `lib/` and `bin/` found no name the gate misses, apart from the `API3_AUTOPRUNE_` prefix
and the `EPUSHOVER_*` error codes. Not on dev: `QUERY_REGEX_*`, `CONTROLLER_REGISTRATION` (in draft
#8857) and any other registration setting. `TRUST_PROXY` and `DEBUG_LOGGING` were already in the 277.

## 3. Contested settings, for the maintainer

1. **`AUTH_DEFAULT_ROLES`, `TREATMENTS_AUTH` (T today).**
   - Options: free T; T limited to a hoster list (`denied`, `readable`, `status-only`) with `denied` as
     the multi default; D.
   - Free T lets one owner make their site anonymously writable: `TREATMENTS_AUTH=off` appends
     `careportal` (`env.js:226-227`).
   - Proposed: the limited list. No `TREATMENTS_AUTH` under multi; map it to roles.
2. **`API_SECRET`, `API_SECRET_FILE` (B).** "Read only by single" assumed separate executables, and D21's one
   entrypoint removes that boundary. Proposed: under `TENANCY_MODE=multi`, refuse to start while either is
   set, so that D13 is a check rather than a convention.
3. **`IMPORT_CONFIG` (D).** `bootevent.js:123-145` fetches a URL and deep-merges it into the settings,
   which under multi is a deployment-wide write into per-tenant state (against D15). Proposed: B, ignored
   with a warning under multi.
4. **Outbound endpoints (T).** This covers `CONNECT_SOURCE_ENDPOINT`, `CONNECT_*_SERVER`,
   `WEBHOOK_HOST`, `WEBHOOK_PORT`, `WEBHOOK_PROTOCOL`, `WEBHOOK_PATH`, `BASE_URL`, and the enables for
   connect, webhook, maker and pushover.
   - As free T, each tenant can make the server send requests from the hoster's network (server-side
     request forgery).
   - Proposed: a hoster allow-list of vendor hosts, with webhooks to public addresses only. `BASE_URL`
     is derived from the tenant slug, not offered.
5. **`TRUST_PROXY` (D).** Empty means every forwarded header is trusted, so the failed-login delay does
   not slow guessing (`delaylist.js:81-86`). Proposed: under multi, refuse to start while it is empty;
   require a hop count or CIDR.
6. **`WRITE_VALIDATION` (new).** D keeps one API contract on the host. T lets an owner loosen it, which
   turns off the unit-plausibility checks (`write-validation.js:19-22`). Proposed: D, with the hoster
   pinning at least `log`; an owner may tighten it, never loosen it.
7. **`API3_SETTINGS_STRICT_READ_ENABLED` (new).** Dev's default is off, so any read token can fetch an
   app's settings record by identifier (`README.md:367`). Proposed: T, default on under multi.
8. **`API3_SECURITY_ENABLE` (D).** Off means API v3 with no token (`README.md:365`). Proposed: not
   settable under multi; refuse to start if false.
9. **`API3_AUTOPRUNE_*` (T): permanent deletion** (`README.md:370-372`). A typo destroys glucose,
   treatment and pump history. Proposed: T with a hoster minimum, an explicit confirmation, and an
   export offered first.
10. **Alarm thresholds and enables (T).** T is right. Open: partial mmol overrides being rewritten
    silently (J11, BF-67), and alarms being off under multi (§7a of the execution plan). Proposed: hide
    alarm settings, with a plain-language explanation, until multi-mode alarms are on.
11. **Plugin credentials (TS)**: `PUSHOVER_*`, `LOOP_APNS_KEY`, `LOOP_APNS_KEY_ID`,
    `LOOP_DEVELOPER_TEAM_ID`, and the connector accounts.
    - Open: whether the hoster can decrypt them (J5), which decides whether server-side Share or
      CareLink polling exists at all.
    - Open: whether `PUSHOVER_API_TOKEN` is D (the hoster's Pushover app), with only the user and alarm
      keys as TS.
    - APNs keys stay TS: the key belongs to the Apple team that built that family's Loop.
    - Proposed: decryptable only inside the connector process, plus the Pushover split.
12. **`DEBUG_LOGGING` (D) and `DBSIZE_*` (T).** `DEBUG_LOGGING` writes record payloads to the log
    (`log-privacy.js:124-136`); as D under multi it would log every tenant's payloads. Proposed: pinned
    off under multi. `dbsize` reads deployment-wide statistics (`dbsize.js:33,42`; what the storage
    layer returns under multi is not checked). Proposed: X under multi until storage is accounted per
    tenant.

- **B.4's totals** (277, and the transcript's union of 247) are true of `81a1f6ce` only; dev measures 264
  and 260.
- **B.2's gaps 1 to 3 and J14** are closed on dev (`env.js:309-336`).

  (`bridge-connect-compat.js:7-11`).
- **`BRIDGE_*` and `MMCONNECT_*`** are listed as live plugin settings; they are now aliases.
- **B.5(ii)'s `MONGODB_COLLECTION`** is fixed on dev.
- **The B.4 note and D5** name four hosted entrypoints, and §F.1 names `bin/admin.js`. D21's
  `nightscout serve <roles>` supersedes both.
- **I.3 (`IMPORT_CONFIG`)** is answerable from the code (§3 item 3).
- **The identity half** assumes Kratos. D17, as amended on 2026-10-27, makes the provider
  interchangeable; no class depends on it.
- **The gate itself**, run on dev, drops the seam's tenancy names until the seam lands. It needs a
  second baseline or an allow-list of seam-only names.
