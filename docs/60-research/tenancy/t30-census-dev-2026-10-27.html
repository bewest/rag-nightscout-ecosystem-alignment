    The tenant configuration census, re-measured on dev (2026-10-27)¶

    Record

    Record as of 2026-10-27. A point-in-time document; it is not kept up to date.

    Contributor-facing. Snapshot, 2026-10-27: cgm-remote-monitor official/dev 7abe1cf6, against the census taken on the seam branch 81a1f6ce (queue T30-RESEARCH). Measured with this repository's census gate; the per-name lists are read from it. Nothing here is decided: the contested settings in §3 are for the maintainer.

    The tenant-owner configuration surface (§B) classifies every setting a Nightscout site reads as T (the tenant owner may set it), TS (a tenant secret), D (a deployment value the hoster pins), B (bootstrap, single-tenant only) or X (not applicable). It was counted at 277 names on the seam branch. The maintainer asked for it to be re-measured on dev before the decisions are walked through.

    1. Count¶

    node tools/queue/gates/t30-census-differential.js --ref 81a1f6ce      # 11 checked, 0 failing; code 277
node tools/queue/gates/t30-census-differential.js --ref official/dev  # 11 checked, 4 failing; code 264

    264 on dev = 277 − 21 + 8, reproduced by session -ee. A git grep of every readENV-style literal in lib/ and bin/ found no name the gate misses, apart from the API3_AUTOPRUNE_ prefix and the EPUSHOVER_* error codes. Not on dev: QUERY_REGEX_*, CONTROLLER_REGISTRATION (in draft

    8857) and any other registration setting. TRUST_PROXY and DEBUG_LOGGING were already in the 277.¶

    3. Contested settings, for the maintainer¶

    Decided in principle 2026-10-27 (maintainer), as D22 (execution plan §2.13): a per-setting operator policy (default, open/bounded/pinned, constraint) over owner values, under project floors that no operator can loosen. Items 2, 3, 5 and 8 and parts of 1, 4, 6 and 12 become floors; the rest become policy rows. Each item re-stated under D22 is still owed. The proposals below are as written before the decision.

    1. AUTH_DEFAULT_ROLES, TREATMENTS_AUTH (T today).
    2. Options: free T; T limited to a hoster list (denied, readable, status-only) with denied as the multi default; D.
    3. Free T lets one owner make their site anonymously writable: TREATMENTS_AUTH=off appends careportal (env.js:226-227).
    4. Proposed: the limited list. No TREATMENTS_AUTH under multi; map it to roles.
    5. API_SECRET, API_SECRET_FILE (B). "Read only by single" assumed separate executables, and D21's one entrypoint removes that boundary. Proposed: under TENANCY_MODE=multi, refuse to start while either is set, so that D13 is a check rather than a convention.
    6. IMPORT_CONFIG (D). bootevent.js:123-145 fetches a URL and deep-merges it into the settings, which under multi is a deployment-wide write into per-tenant state (against D15). Proposed: B, ignored with a warning under multi.
    7. Outbound endpoints (T). This covers CONNECT_SOURCE_ENDPOINT, CONNECT_*_SERVER, WEBHOOK_HOST, WEBHOOK_PORT, WEBHOOK_PROTOCOL, WEBHOOK_PATH, BASE_URL, and the enables for connect, webhook, maker and pushover.
    8. As free T, each tenant can make the server send requests from the hoster's network (server-side request forgery).
    9. Proposed: a hoster allow-list of vendor hosts, with webhooks to public addresses only. BASE_URL is derived from the tenant slug, not offered.
    10. TRUST_PROXY (D). Empty means every forwarded header is trusted, so the failed-login delay does not slow guessing (delaylist.js:81-86). Proposed: under multi, refuse to start while it is empty; require a hop count or CIDR.
    11. WRITE_VALIDATION (new). D keeps one API contract on the host. T lets an owner loosen it, which turns off the unit-plausibility checks (write-validation.js:19-22). Proposed: D, with the hoster pinning at least log; an owner may tighten it, never loosen it.
    12. API3_SETTINGS_STRICT_READ_ENABLED (new). Dev's default is off, so any read token can fetch an app's settings record by identifier (README.md:367). Proposed: T, default on under multi.
    13. API3_SECURITY_ENABLE (D). Off means API v3 with no token (README.md:365). Proposed: not settable under multi; refuse to start if false.
    14. API3_AUTOPRUNE_* (T): permanent deletion (README.md:370-372). A typo destroys glucose, treatment and pump history. Proposed: T with a hoster minimum, an explicit confirmation, and an export offered first.
    15. Alarm thresholds and enables (T). T is right. Open: partial mmol overrides being rewritten silently (J11, BF-67), and alarms being off under multi (§7a of the execution plan). Proposed: hide alarm settings, with a plain-language explanation, until multi-mode alarms are on.
    16. Plugin credentials (TS): PUSHOVER_*, LOOP_APNS_KEY, LOOP_APNS_KEY_ID, LOOP_DEVELOPER_TEAM_ID, and the connector accounts.
      • Open: whether the hoster can decrypt them (J5), which decides whether server-side Share or CareLink polling exists at all.
      • Open: whether PUSHOVER_API_TOKEN is D (the hoster's Pushover app), with only the user and alarm keys as TS.
      • APNs keys stay TS: the key belongs to the Apple team that built that family's Loop.
      • Proposed: decryptable only inside the connector process, plus the Pushover split.
    17. DEBUG_LOGGING (D) and DBSIZE_* (T). DEBUG_LOGGING writes record payloads to the log (log-privacy.js:124-136); as D under multi it would log every tenant's payloads. Proposed: pinned off under multi. dbsize reads deployment-wide statistics (dbsize.js:33,42; what the storage layer returns under multi is not checked). Proposed: X under multi until storage is accounted per tenant.

    3a. The twelve re-stated under D22 (draft for the maintainer, 2026-10-27)¶

    Draft, reviewed 2026-10-27: the maintainer made row 7 a floor; the other rows stand as drafted. Each row applies D22 (execution plan §2.13) to one contested item: floor is enforced in code under multi and no operator can loosen it; policy is the operator's per-setting row (default, mode, constraint), which an operator may override per tenant; owner is what the tenant owner sets within it. Rows marked check carry a choice the decisions so far do not settle.

    # settings floor (code, multi only) operator policy owner check
    1 AUTH_DEFAULT_ROLES, TREATMENTS_AUTH default roles only from denied, readable, status-only; TREATMENTS_AUTH not offered (it would append careportal for anonymous visitors) bounded: allowed list within the floor's three (an operator may narrow it); default denied picks from the operator's list —
    2 API_SECRET, API_SECRET_FILE refuse to start while either is set none none (each tenant's root credential is in the secrets component, D13) —
    3 IMPORT_CONFIG ignored, with a warning naming it none none —
    4 outbound endpoints: CONNECT_*, WEBHOOK_*, BASE_URL, the connect / webhook / maker / pushover enables connector endpoints only the hosts a driver defines; webhooks to public addresses only; BASE_URL derived from the tenant slug, never set which integration kinds are enabled, how many of each per tenant, and an optional host allow-list for webhooks adds, tests and removes integration records (D22: typed records) —
    5 TRUST_PROXY refuse to start while empty; a hop count or CIDR a deployment value, pinned; never a tenant row none dev's default is empty, so every operator must set it
    6 WRITE_VALIDATION at least log bounded: log or reject; the operator sets the default may tighten (log to reject), never loosen below the operator's value dev's default is off, so every operator must set it
    7 API3_SETTINGS_STRICT_READ_ENABLED always on under multi (decided 2026-10-27): reading an app's settings record by identifier needs api:settings:admin, as search and history do none none —
    8 API3_SECURITY_ENABLE refuse to start if false none none —
    9 API3_AUTOPRUNE_* (permanent deletion) an explicit confirmation, with an export offered first bounded: a minimum retention per collection; default off may turn pruning on above the operator's minimum —
    10 alarm thresholds and enables hidden, with a plain-language explanation, until multi-mode alarms pass the alarm gate (decided 2026-10-27; execution plan §7a) after the gate: open, with an operator default per threshold after the gate: sets thresholds, stored in mg/dL; a partial mmol override must not be rewritten silently (BF-67) first —
    11 plugin credentials: PUSHOVER_*, LOOP_APNS_*, connector logins encrypted at rest; decrypted only by the consuming process; the operator plane never reveals which integration kinds are enabled; an operator-owned part where a kind declares one (the Pushover application token) owner-owned parts (Pushover user and alarm keys, APNs key and team, connector logins), revealed only through the logged reveal —
    12 DEBUG_LOGGING; DBSIZE_* DEBUG_LOGGING off; dbsize not offered until storage is accounted per tenant none none —

    The eight names new on dev (§2) under the same rules: WRITE_VALIDATION is row 6; API_V3_DATA_WARNINGS, API_V1_COUNT_LEADING_NUMBER and API_V1_COUNT_ZERO_WINDOW are deployment values the operator pins (release-driven compatibility switches); API3_SETTINGS_STRICT_READ_ENABLED is row 7 (a floor); SHOW_SECONDS is open to the owner; CUSTOMCONNSTR_API3_MAX_LIMIT and CUSTOMCONNSTR_DEXCOM_BRIDGE_USE_LEGACY are not offered under multi.

    What follows for the schema. Rows 2, 3, 5, 8 and 12 are not policy rows at all. Rows 4 and 11 move out of the settings table into integration records and the secrets component. Row 7 is a floor. That leaves policy rows for 1, 6, 9 and 10 among the twelve.

    4. Stale in the configuration-surface document¶

    • B.4's totals (277, and the transcript's union of 247) are true of 81a1f6ce only; dev measures 264 and 260.
    • B.2's gaps 1 to 3 and J14 are closed on dev (env.js:309-336).
    • B.6 calls DEXCOM_BRIDGE_USE_LEGACY absent. On dev it is read, warned about and ignored (bridge-connect-compat.js:7-11).
    • BRIDGE_* and MMCONNECT_* are listed as live plugin settings; they are now aliases.
    • B.5(ii)'s MONGODB_COLLECTION is fixed on dev.
    • The B.4 note and D5 name four hosted entrypoints, and §F.1 names bin/admin.js. D21's nightscout serve <roles> supersedes both.
    • I.3 (IMPORT_CONFIG) is answerable from the code (§3 item 3).
    • The identity half assumes Kratos. D17, as amended on 2026-10-27, makes the provider interchangeable; no class depends on it.
    • The gate itself, run on dev, drops the seam's tenancy names until the seam lands. It needs a second baseline or an allow-list of seam-only names.
