# Definition of done — downstream ready

*Contributor-facing. Applies to every document under `docs/00-overview`,
`docs/30-design/{remedial,modernization,tenancy,platform}`,
`docs/60-research/{remedial,modernization,tenancy,programme}`, `queue/` and
`reports/reviewer-packets/`. Adopted 2026-09-22.*

A document is **downstream ready** when someone who has never read this
repository's history — an upstream reviewer, the maintainer deciding a release,
an operator, a clinician reviewing a draft — can act on it without asking what
changed or whom to believe.

## The criteria

1. **Current facts only.** The document says what is true now. It does not
   narrate how the project came to believe it: no "was X, then Y, now Z" chains,
   no "an earlier draft said", no "this claim is retracted", no running tallies of
   past mistakes. A wrong claim is corrected in place. The history is in git.
2. **Dated and anchored.** Every measured fact names the date and the commit it
   was measured against (`origin/dev 74fc6619`, not "dev"). A count that moves
   (commits behind, open defects) is either generated by a gate or given with the
   command that reproduces it.
3. **Provenance marked.** Each defect claim says **reproduced** (run, with a
   control where the claim is about access or severity) or **read-derived**
   (inferred from source, not run). A read-derived fix is a hypothesis.
4. **Status words mean one thing.** `open` · `fixed` (on a branch, not merged) ·
   `merged` (in `dev`, not released) · `released` (in a tagged release operators
   run). Nothing is described as fixed for operators until it is `released`.
5. **Audience declared.** The first lines say contributor-facing or user-facing.
   User-facing text uses plain language, defines jargon, keeps every safety
   caveat, gives no individual dosing advice, says it is not medical advice, and
   points to the reader's care team where relevant.
6. **Mechanism, not recipe.** A defect that is live on the shipping release is
   described by mechanism only. No request, payload or pattern that would work
   against a deployed instance appears in this public repository.
7. **One home per fact.** Defect facts live in the backfix register, item state
   in `queue/work-queue.yaml`, decisions in the execution plan. Other documents
   link rather than restate, so there is one place to correct.
8. **Links resolve.** `make docs-links` passes; generated views pass
   `make views-check` and `make packets-check`.
9. **No PII or health data.** No names, emails or identifiers from user data,
   logs or exports; no credentials.
10. **Sendable artifacts are send-ready.** A drafted PR body, advisory reply or
    release note can be pasted as-is: no internal ids a recipient cannot resolve,
    no notes-to-self, and it is marked draft until a human sends it.

## Living documents and snapshots

**Living documents** are kept current and must meet every criterion: the
overview pages, the backfix register, the queue and its README, the execution
plan, the release-versioning policy, and any drafted outgoing artifact.

**Dated research and design documents** (a date in the filename) are
**snapshots**. They are not rewritten as the world moves. Each carries a status
line under its title stating the date and commit it describes, whether it is
current or superseded, and where the current fact lives. Known-wrong claims in a
snapshot are corrected in place with a one-line note, not left for the reader to
discover.

**A series is one living document.** When the same deliverable is produced
repeatedly — successive test runs of one release candidate, revisions of one
plan — it lives in one file with no date in its name. The current version is
given in full. Each earlier version is one row in a history table that links to
the file at the commit holding it. Checks that the current version did not repeat
are carried forward, each naming the tree it ran on. Superseded files are removed
from the working tree rather than kept beside the current one. The first such
record is [the 15.0.9 integration record](../30-design/remedial/rc-15.0.9-integration-record.md).

## What this is not

It is not a style guide and not a length limit. A long document that meets the
criteria is done; a short one that says "see the thread" is not.
